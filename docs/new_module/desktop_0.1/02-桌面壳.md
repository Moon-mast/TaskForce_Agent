# 02 桌面壳:`src/desktop/`(第 8 个包)

> 前置:[01-路径层重构](01-路径层重构.md) 已完成。
> 验收:`uv run python -m desktop` 起来一个原生窗口,界面可用,关窗后进程干净退出。

## 1. 为什么是第 8 个包

项目既有逻辑是「一个入口一个包」:`cli/` = 终端入口、`api/` = HTTP 入口。
桌面壳是第三个入口,与两者并列,所以 `src/desktop/`。它**只做壳**——
窗口、生命周期、预检;业务一律仍走 `build_graph()` / `run_turn()`(AGENTS.md 双入口红线)。

| 文件 | 职责 | 行数量级 |
|---|---|---|
| `const.py` | 共享常量(端口、gui、窗口尺寸、各类超时) | 20 |
| `bootstrap.py` | **必须最先跑**:环境注入 + 控制台兜底 + 数据目录 | 80 |
| `preflight.py` | 预检:配置 / 端口 / PostgreSQL | 90 |
| `server.py` | 进程内 uvicorn(后台线程)+ 就绪轮询 | 70 |
| `setup_window.py` | 统一故障窗口(中文原因 + 重试 + 打开配置) | 120 |
| `shutdown.py` | 关窗退出分层兜底 | 60 |
| `app.py` | 主窗口 + 生命周期编排 | 90 |
| `__main__.py` | 入口 + `--tf-` 自定义开关 | 40 |

## 2. 已核实的 API 事实(本方案的依据,勿凭记忆改)

写代码前逐条实测过,列在这里免得以后被"想当然"改坏:

| 事实 | 出处 |
|---|---|
| `webview.start(func, args, localization, gui, debug, http_server, http_port, user_agent, **private_mode=True**, storage_path, menu, server, server_args, ssl, icon)` | pywebview 6.2.1 实测签名 |
| `private_mode` 默认 **True** —— 不显式关掉,每次退出清空 localStorage | 同上 |
| `storage_path` 是 `start()` 的参数,**不是** `create_window()` 的 | 同上 |
| `GUIType = Literal['qt','gtk','cef','mshtml','edgechromium','android','cocoa']`;不指定 gui 时按平台挑,**Windows 上可能落到 `mshtml`(IE11)** | `webview/guilib.py:14` |
| `create_window()` 在 `start()` 之后调用**可以立即建窗口**,但要求**非主线程** | `webview/__init__.py:416-417` |
| js_api 方法从 JS 侧以 `window.pywebview.api.<name>()` 调用(返回 Promise) | `webview/js/api.js:59` |
| `create_window(text_select=False)` 是默认值 —— 不显式开,窗口里**选不中文字**,用户复制不了回答 | 实测签名 |
| `is_local_url("http://127.0.0.1:8010/")` 为 **False** → pywebview **不会**再包一层自己的 http server → SSE 不受影响 | `webview/util.py:75-84` |
| uvicorn 0.52.4 的 `capture_signals` **显式跳过非主线程** → 可以安全地在后台线程 `Server.run()` | `uvicorn/server.py:322-327` |

> (`mcp_meta` 超时 60s)。所以首轮等几十秒是正常的,别误判成卡死。

## 4. `src/desktop/bootstrap.py`

```python
"""桌面壳启动前置:环境注入 + 控制台兜底 + 数据目录准备。

**必须在任何 app 模块被 import 之前调用。** 两个理由:
① `settings/config.py` 的 `_ENV_FILE` 是**模块级常量**,import 时就定死;
② 全项目有 6 个 lru_cache(`get_settings` / `embedding_dim` / `mcp_meta` / `_skills_meta` /
   `load_agents_md` / `rag_v01._cfg`),任何一个在错误环境下被调过一次,进程内就**永久锁死**。

使用位置:
    - desktop/app.py:main() 第一行;
    - desktop/__main__.py:smoke() 第一行。
"""
import os
import sys
from pathlib import Path

from dotenv import load_dotenv

from settings.appdirs import data_root, ensure_data_layout, env_file

LOG_DIR_NAME = "logs"
LOG_FILE_NAME = "desktop.log"


def inject_env() -> None:
    """把路径类配置注入进程环境,并载入 .env。

    为什么需要这一步:`pydantic` 的 `env_file` 只读给自己的 Settings 类,**不写 os.environ**;
    而 `rag_v01/config.py` 明确「不读 .env,载入由入口负责」,只认**进程环境变量**;
    E2B SDK 同理(`settings/config.py` 里那条「client 运行时把它们回注 os.environ」的注释
    说的就是这个缺口)。

    一律 setdefault:`TASKFORCE_HOME` 若由外部显式给了值,以外部为准(部署逃生口)。
    """
    root = data_root()
    os.environ.setdefault("TASKFORCE_HOME", str(root))
    # 重构前这两个默认值都是 CWD 相对(data/rag2_images 与 ~/.cache/huggingface),
    # 冻结后 CWD 不可控、~/.cache 会偷偷长到 500MB 且卸载不清理
    os.environ.setdefault("RAG2_IMAGE_DIR", str(root / "data" / "rag2_images"))
    os.environ.setdefault("HF_HOME", str(root / "models"))
    # 只读安装目录下 Python 会尝试写 .pyc 并失败(杀软/企业策略下还会弹窗)
    os.environ["PYTHONDONTWRITEBYTECODE"] = "1"
    env = env_file()
    if env.is_file():
        load_dotenv(env)


def install_console_shim() -> Path | None:
    """windowed 冻结下 `sys.stdout`/`sys.stderr` 是 `None`,把两者接到日志文件。

    不装的后果有两层,第二层更阴:
    ① `api/main.py` 与 `cli/repl.py` 的无条件 `sys.stdout.reconfigure` 在 import 期
       抛 `AttributeError`,进程直接起不来;
    ② `print(x, file=sys.stderr)` 在 `file=None` 时**不是异常,而是静默 no-op** ——
       `agent/tasks.py` 的任务异常、`tools/skills/loader.py` 的「跳过 xxx:缺少 SKILL.md」、
       `tools/mcp/client.py` 的「服务器不可达已跳过」会**全部变哑巴**,让人误判那些代码
       路径根本没被执行。

    `buffering=1`(行缓冲)是硬要求:退出兜底走 `os._exit` 不 flush,块缓冲下最后几行
    —— 也就是崩溃前最关键的几行 —— 会被丢掉。

    有真控制台时(console 变体)原样不动:那个变体就靠控制台看输出,两条通道各自单一。
    """
    if sys.stdout is not None and sys.stderr is not None:
        return None
    log_path = data_root() / LOG_DIR_NAME / LOG_FILE_NAME
    log_path.parent.mkdir(parents=True, exist_ok=True)
    stream = open(log_path, "a", encoding="utf-8", buffering=1)
    sys.stdout = stream
    sys.stderr = stream
    return log_path


def prepare() -> Path | None:
    """入口第一步:注入环境 → 装控制台兜底 → 准备数据目录。返回日志路径(无则 None)。

    幂等:入口会先调一次(为了赶在 import app 模块之前注入环境),`app.main()` 里还会再调
    一次(为了让直接调用 `app.main()` 的场景也自洽)。用显式标志位挡住第二次,而不是
    「碰巧无害」—— 控制台兜底那段若跑第二次会把已经接上的日志流再包一层。
    """
    global _PREPARED, _LOG_PATH
    if _PREPARED:
        return _LOG_PATH
    inject_env()
    _LOG_PATH = install_console_shim()
    ensure_data_layout()
    _PREPARED = True
    return _LOG_PATH
```

模块顶部随之加两个私有状态:

```python
_PREPARED = False
_LOG_PATH: Path | None = None
```

## 5. `src/desktop/preflight.py`

```python
"""启动前预检:配置 / 端口 / PostgreSQL。结论交给 setup_window 呈现。

设计取向:能提前发现的失败就提前发现,并且**给中文的下一步动作**。
`api/main.py` 的 lifespan 连不上库时只会让 uvicorn 打印一行
`Application startup failed. Exiting.` 然后以 exit 3 退出,原生没有任何 GUI 报错路径 ——
在桌面壳里那表现为「双击后窗口闪一下就没了」,所以这一层是必须的。
"""
import socket
from dataclasses import dataclass

import psycopg
from pydantic import ValidationError

from desktop import const
from settings.config import get_settings
from settings.db.base import ensure_vector_ext


@dataclass(frozen=True)
class Result:
    """预检结论。ok=False 时三个字段由故障窗口原样展示。"""
    ok: bool
    title: str = ""
    detail: str = ""
    hint: str = ""


def run() -> Result:
    """按「配置 → 端口 → 数据库」顺序检查,第一个失败即返回。"""
    failed = _check_config()
    if failed is not None:
        return failed
    failed = _check_port()
    if failed is not None:
        return failed
    return _check_database(get_settings().database_url) or Result(ok=True)


def _check_config() -> Result | None:
    """校验 .env。

    **必须先 cache_clear**:用户在故障窗口里点「重试」时,可能刚改完 .env;
    `get_settings` 是 lru_cache,不清缓存拿到的是旧的失败结果,表现为「改了没用」。
    """
    get_settings.cache_clear()
    try:
        get_settings()
    except RuntimeError as exc:
        # assert_ready 的中文报错,原样展示,不重写
        return Result(
                ok=False,
                title="模型配置未完成",
                detail=str(exc),
                hint="点「打开配置文件」填写后,再点「重试」。",
        )
    except ValidationError as exc:
        # .env 缺失或键名写坏时走这条:Settings() 先于 assert_ready(),
        # 抛的是 pydantic 的 ValidationError,可读性差,所以补一段自己的说明
        return Result(
                ok=False,
                title="配置文件无法解析",
                detail=str(exc),
                hint="点「打开配置文件」对照 .env.example 修正后,再点「重试」。",
        )
    return None


def _check_port() -> Result | None:
    """8010 必须空闲。

    **不做「占用则顺延」**:前端把会话 id 等状态存在 localStorage,而 localStorage
    **按 origin 隔离** —— 端口一变等于换了个应用,每次启动都会丢状态。
    所以宁可明确报错,也不静默换端口。
    """
    with socket.socket() as probe:
        probe.settimeout(const.PORT_PROBE_TIMEOUT)
        if probe.connect_ex((const.HOST, const.PORT)) != 0:
            return None
    return Result(
            ok=False,
            title=f"端口 {const.PORT} 已被占用",
            detail="可能已经有一个 TaskForce 在运行。",
            hint="关掉那一个窗口(或在任务管理器里结束它)后,点「重试」。",
    )


def _check_database(database_url: str) -> Result | None:
    """探 PostgreSQL,并幂等创建 pgvector 扩展。

    在这里建扩展而不是等 `get_store()`:后者的首次调用发生在「第一次用到记忆工具」,
    那时如果 PG 起着但 pgvector 没装,会变成**对话中途报错** ——
    而启动一切正常、`/health` 也报 ok,极难定位。
    """
    try:
        ensure_vector_ext(database_url)
    except psycopg.Error as exc:
        return Result(
                ok=False,
                title="PostgreSQL 连不上",
                detail=str(exc).strip(),
                hint="在项目目录执行 docker compose up -d 起库(主机端口 5433),再点「重试」。",
        )
    return None
```

> **Milvus 故意不做预检**。`rag_v01` 承诺「无 import 副作用:不连 Milvus、不建目录」,
> 知识库侧全是懒加载,所以 Milvus 没起**不影响启动也不影响对话**,只在用到知识库时报错,
> 而知识库页会把错误直接显示出来。为它加一道门槛只会让「没装 Milvus 就用不了桌面应用」,
> 那是退步。

## 6. `src/desktop/server.py`

```python
"""进程内后端服务:uvicorn 跑在后台线程,端口固定,就绪以 `GET /` 判定。

与 `api/main.py` 的 `__main__` 段有三处刻意差别,都被冻结环境逼出来的:
① **不带 reload**:它是纯开发设置,会另起 reloader 父进程 + 子进程并监视文件系统,
   冻结后表现为进程树失控、关窗杀不干净;
② **传 app 对象而不是 `"api.main:app"` 字符串**:字符串形式要求 `sys.path` 含 `src/`,
   冻结后不成立;对象形式不依赖 import 路径;
③ **不使用 8010 之外的端口**,且占用时由 preflight 明确报错(理由见 preflight)。
"""
import threading
import time
import urllib.error
import urllib.request

import uvicorn

from desktop import const


class Server:
    """uvicorn 的进程内包装。start() 非阻塞,wait_ready() 轮询根路径。"""

    def __init__(self, host: str = const.HOST, port: int = const.PORT) -> None:
        self._host = host
        self._port = port
        self._server: uvicorn.Server | None = None
        self._thread: threading.Thread | None = None

    @property
    def url(self) -> str:
        return f"http://{self._host}:{self._port}/"

    def start(self) -> None:
        """起 uvicorn(幂等:重复调用不会起第二个)。

        `from api.main import app` 放在函数体内而**不是模块顶层**是有意的:
        该 import 会连带把 `settings.config` 拉进来,而它的 `_ENV_FILE` 是模块级常量,
        import 即定死。放函数体内才能保证 bootstrap 的环境注入一定更早发生。
        """
        if self._thread is not None:
            return
        from api.main import app

        config = uvicorn.Config(
                app,
                host=self._host,
                port=self._port,
                log_level="info",
        )
        self._server = uvicorn.Server(config)
        # daemon=True:即便退出序列的兜底没走到,也不让这个线程吊住解释器
        self._thread = threading.Thread(target=self._server.run, name="uvicorn", daemon=True)
        self._thread.start()

    def wait_ready(self, timeout: float = const.READY_TIMEOUT) -> bool:
        """轮询根路径直到返回 HTML。

        **为什么不轮询 `/health`**:它会真的调 `sandbox_health()` → `Sandbox.create()`,
        耗时数秒而且**开始计费**(云端实例 TTL 3600s,按存活时长计费)。

        轮询 `GET /` 一次同时验证两件事:uvicorn 已监听 **且** 前端产物已正确挂载。
        dist 没收集进包时这里会一直 404,于是「服务不就绪」直接指向
        「前端产物没打进去」这个根因 —— 比拿到「服务正常但窗口白屏」有用得多。
        """
        deadline = time.monotonic() + timeout
        while time.monotonic() < deadline:
            if self._is_up():
                return True
            time.sleep(const.READY_INTERVAL)
        return False

    def stop(self) -> None:
        """请求 uvicorn 停下(不阻塞等待线程结束)。"""
        if self._server is not None:
            self._server.should_exit = True

    def _is_up(self) -> bool:
        """根路径返回 HTML 才算就绪(避免把别的服务误认成自己)。"""
        try:
            with urllib.request.urlopen(self.url, timeout=const.HTTP_PROBE_TIMEOUT) as resp:
                body = resp.read(512)
        except (urllib.error.URLError, OSError):
            return False
        return b"<" in body
```

## 7. `src/desktop/setup_window.py`

```python
"""预检未通过时的统一故障窗口:中文原因 + 「重试」/「打开配置文件」。

复用理由:首启缺配置、PG 没起、端口被占 —— 用户面对的都是同一件事
「应用没起来,原因是 X,下一步做 Y」。**一个窗口 + 两个按钮覆盖全部失败路径,不新增表单。**
用户配置填完后不必重启:点「重试」就地重跑预检(见 preflight._check_config 的 cache_clear)。
"""
import html
import os
from collections.abc import Callable

import webview

from desktop import const
from desktop.preflight import Result

_WINDOW: webview.Window | None = None


class SetupApi:
    """暴露给故障窗口 JS 的桥(JS 侧 `window.pywebview.api.do_retry()`)。

    只做转发:真正的重试逻辑在 app.py(它才知道怎么起服务、开主窗口),
    这样 setup_window 不反向依赖 app,避免循环 import。
    """

    def __init__(self, on_retry: Callable[[], dict]) -> None:
        self._on_retry = on_retry

    def do_retry(self) -> dict:
        """重跑预检。返回 {"ok": bool, ...};ok=False 时带新的原因供 JS 重绘。"""
        return self._on_retry()

    def open_config(self) -> None:
        """用系统默认程序打开 .env。

        `os.startfile` 是 Windows 专有 —— 本项目桌面壳只面向 Windows
        (pywebview 的 edgechromium 后端、onedir exe 也都是 Windows 形态),不额外抽象。
        """
        path = env_file()
        if not path.parent.exists():
            path.parent.mkdir(parents=True, exist_ok=True)
        if not path.exists():
            path.write_text("", encoding="utf-8")
        os.startfile(path)


def show(result: Result, on_retry: Callable[[], dict]) -> webview.Window:
    """建故障窗口(不调用 webview.start(),由 app.py 统一启动 GUI 循环)。"""
    global _WINDOW
    _WINDOW = webview.create_window(
            title=f"{const.APP_TITLE} — 启动检查未通过",
            html=_page(result),
            js_api=SetupApi(on_retry),
            width=const.SETUP_WINDOW_SIZE[0],
            height=const.SETUP_WINDOW_SIZE[1],
            text_select=True,
    )
    return _WINDOW


def close() -> None:
    """关掉故障窗口。**必须在主窗口建好之后再调** —— 否则会出现「一个窗口都没有」的瞬间,
    `webview.start()` 在所有窗口关闭时就返回,整个 GUI 循环会提前结束。
    """
    global _WINDOW
    if _WINDOW is not None:
        _WINDOW.destroy()
        _WINDOW = None


def _page(result: Result) -> str:
    """渲染故障页。

    内联 HTML 而非模板文件:`webview.create_window(html=...)` 走的是 pywebview 的
    内置 data URI,不需要它再起一个 http server(少一层,也不影响后面主窗口的 SSE)。
    三个插槽全部经 html.escape —— detail 里是 pydantic / psycopg 的原始报错,可能含尖括号。
    """
    return Template(_TEMPLATE).substitute(
            title=html.escape(result.title),
            detail=html.escape(result.detail),
            hint=html.escape(result.hint),
    )


# 占位符用 $name(string.Template)而不是 str.format 的 {name}:
# 这个模板里既有 CSS 的花括号又有 JS 的花括号,用 str.format 就得把每一处字面括号
# 都写成 {{}},漏一处就是 KeyError 或花括号消失。项目的提示词加载(settings/loader.py)
# 定的就是这条规矩:占位符一律 $name,避免与花括号冲突。这里沿用同一条。
_TEMPLATE = """<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<title>TaskForce 启动检查</title>
<style>
  body { font-family: "Microsoft YaHei", system-ui, sans-serif; margin: 0; padding: 32px 36px;
         color: #1f2328; background: #fbfbfd; }
  h1 { font-size: 19px; margin: 0 0 14px; }
  .detail { white-space: pre-wrap; word-break: break-all; background: #fff;
```

## 8. `src/desktop/shutdown.py`

```python
"""关窗退出序列:分层兜底,保证窗口消失后进程一定结束。

为什么需要这么麻烦?
    `agent/tasks.py` 的 `ThreadPoolExecutor` **worker 非 daemon**,而 CPython 3.9+ 在
    解释器退出时经 `threading._register_atexit` **join 所有 worker**;同时 `tasks.py` 的
    `_run()` 是同步 `graph.invoke`、**不可取消**,子图是 `MAX_ITERATIONS=12` 的 ReAct 循环,
    每轮可能跑一次最长 60s 的沙箱调用。
    结论:`cancel_futures=True` **只能取消尚未启动的任务**,正在跑的照样把进程按住 ——
    所以「优雅关闭」单独用是不够的,必须有硬兜底。

已知取舍(写在这里,免得以后当成 bug 修):
    硬兜底走 `os._exit`,会**丢弃正在执行的子图任务**(其结果不入账本)。若关闭时正好有
    计划在推进,那个步骤会停在 running —— 下次启动不会自动续跑。
    这与 REPL 里 Ctrl+C 的后果一致,是既有设计,本期不引入断点续跑。
"""
import os
import sys


def finish(server, code: int = 0) -> None:
    """退出序列。永不返回(最后一步是 os._exit)。

    顺序是有讲究的:
    ① 停收新请求 —— 避免退出过程中又起新的沙箱调用;
    ② **先显式回收云沙箱** —— 见下面那段注释,这是唯一有「资损」风险的一步;
    ③ 有界等待,给在跑的收尾一点时间;
    ④ flush 日志 —— 块缓冲下不 flush,崩溃前最后几行正好丢;
    ⑤ 硬退出。
    """
    server.stop()
    _kill_sandbox()
    _flush_logs()
    os._exit(code)


def _kill_sandbox() -> None:
    """显式回收云端沙箱实例。

    `tools/sandbox/client.py` 只在 `atexit` 里注册了 `_kill`,而**下面的 os._exit 会跳过
    全部 atexit** —— 不在这里先补一次,云沙箱就会漏回收,按存活时长计费空转到 TTL(1 小时)。
    所以这条不是「优化」,是防止真实扣费。

    import 放函数体内:`tools/sandbox/client.py` 顶层就会 import `settings.config`,
    而那是「必须在环境注入之后」的模块之一。放这里顺带把它推迟到退出那一刻。
    """
    try:
        from tools.sandbox.client import shutdown as sandbox_shutdown

        sandbox_shutdown()
    except Exception:  # 退出路径不因清理失败而中断
        pass


def _flush_logs() -> None:
    """flush 标准流。bootstrap 把 stdout/stderr 接到了行缓冲日志文件,
    但 pydantic / uvicorn 等也可能持有自己的缓冲。"""
    for stream in (sys.stdout, sys.stderr):
        try:
            if stream is not None:
                stream.flush()
        except Exception:
            pass
```

> `const.EXIT_GRACE` 在这个版本里**没有用上**(序列里没有 join 等待)。留一个常量容易让人
> 以为存在等待上界 —— 要么删掉它,要么按下面的可选增强用起来。
> **可选增强**(想让正在跑的任务有收尾窗口再加):在 ② 与 ⑤ 之间 join uvicorn 线程
> `server._thread.join(timeout=const.EXIT_GRACE)`。当前实现直接硬退,理由是关窗就是用户
> 的明确意图,让它多等 6 秒反而像卡死。

## 9. `src/desktop/app.py`

```python
"""桌面壳主入口:预检 → (失败则故障窗口 + 重试) → 起服务 → 开主窗口 → 关窗退出。

GUI 循环只启动一次(`webview.start()` 在本进程只能调一次,它在所有窗口关闭时返回)。
所以「重试」不是重启进程,而是**在已启动的循环里换窗口** —— 这也是本模块结构
看起来绕的原因。

⚠️ **import 顺序是硬约束**:本模块顶层的 `preflight` → `settings.config` 链会在 import
期间就执行 `settings/config.py` 的模块级 `_ENV_FILE = env_file()`,那一刻环境变量必须
已经注入好。所以入口(`desktop/__main__.py`)必须**先 `bootstrap.prepare()` 再 import 本模块**。
"""
from pathlib import Path

import webview

from desktop import bootstrap, const, preflight, server, setup_window, shutdown
from settings.appdirs import data_root

_server = server.Server()

# 「预检过了但服务起不来」的专用结论:几乎只有一种成因 —— 前端产物没被收集进包
_BACKEND_FAILED = preflight.Result(
        ok=False,
        title="后端未能就绪",
        detail="服务已启动但根路径没有返回页面,通常是前端构建产物没打进包里。",
        hint="开发态请先跑 cd dev/front && npm run build;打包产物请重新构建。",
)


def main(debug: bool = False) -> None:
    """壳入口。函数不返回:`webview.start()` 直到窗口全关才返回,随后走退出序列。"""
    bootstrap.prepare()
    result = preflight.run()
    if not result.ok:
        setup_window.show(result, on_retry=_retry)
    elif not _start_backend():
        setup_window.show(_BACKEND_FAILED, on_retry=_retry)
    else:
        _open_main_window()
    webview.start(
            gui=const.GUI,
            debug=debug,
            # 不显式关掉 private_mode 的话,每次退出都会清空 localStorage,
            # 表现为「应用每次都忘了上次的会话与视图」
            private_mode=False,
            storage_path=str(_storage_dir()),
    )
    shutdown.finish(_server)


def _start_backend() -> bool:
    """起服务并等就绪。失败返回 False(调用方负责把它呈现给用户)。"""
    _server.start()
    return _server.wait_ready()


def _open_main_window() -> webview.Window:
    """开主窗口。

    `text_select=True` 不能省:pywebview 默认 False,会让窗口里**选不中文字**,
    用户复制不了智能体的回答 —— 对一个问答工作台是硬伤。
    """
    return webview.create_window(
            title=const.APP_TITLE,
            url=_server.url,
            width=const.WINDOW_SIZE[0],
            height=const.WINDOW_SIZE[1],
            min_size=const.WINDOW_MIN,
            text_select=True,
    )


def _storage_dir() -> Path:
    """webview 自己的 localStorage / 缓存落点:放应用数据目录,不污染用户 profile。"""
    path = data_root() / const.STORAGE_DIR_NAME
    path.mkdir(parents=True, exist_ok=True)
    return path


def _retry() -> dict:
    """故障窗口「重试」的处理。由 setup_window 的 JS 桥在 worker 线程里调用。

    **顺序不能反:先建主窗口,再销毁故障窗口。** 反过来的话会出现「一个窗口都没有」的
    瞬间,`webview.start()` 在所有窗口关闭时就返回,GUI 循环会提前结束、进程直接退出。
    """
    result = preflight.run()
    if not result.ok:
        return _payload(result)
    if not _start_backend():
        return _payload(_BACKEND_FAILED)
    _open_main_window()
    setup_window.close()
    return {"ok": True}


def _payload(result: preflight.Result) -> dict:
    """把预检结论转成 JS 侧能消费的形状。"""
    return {
        "ok": False,
        "title": result.title,
        "detail": result.detail,
        "hint": result.hint,
    }
```

## 10. `src/desktop/__main__.py`

```python
"""桌面壳进程入口:`uv run python -m desktop`,冻结后是 exe 的入口。

自定义开关一律加 `--tf-` 前缀:**PyInstaller 的 bootloader 会自己消费 `--debug` 一类参数**,
不加前缀会与它打架。

本模块承担一条硬约束:**先 `bootstrap.prepare()` 注入环境,再 import `desktop.app`**。
理由是 app 的顶层 import 会连带把 `settings/config.py` 拉进来,而它的 `_ENV_FILE` 是
**模块级常量**,求值那一刻环境变量必须已经就位。所以下面的 `from desktop import app`
是**函数体内**的延迟 import,不是随手写的。
"""
import sys


def main(argv: list[str] | None = None) -> int:
    """解析开关后分发。返回进程退出码。"""
    args = list(sys.argv[1:] if argv is None else argv)
    if "--tf-smoke" in args:
        return smoke()
    from desktop import bootstrap

    bootstrap.prepare()
    from desktop import app

    app.main(debug="--tf-debug" in args)
    return 0


def smoke() -> int:
    """无窗口自检:预检 → 起服务 → 等就绪 → 汇报 → 退出。

    这是**打包验收的关键工具**:在命令行里就能验证冻结产物是否真的能起来
    (`TaskForce-debug.exe --tf-smoke`),不必靠「点开窗口看一眼」。退出码即结论,
    可以写进脚本断言:
        0 = 正常;2 = 预检未通过;3 = 服务未就绪(多半是前端产物没打进去)。
    用 console 变体跑,输出才看得见;windowed 变体的输出会落到 logs/desktop.log。
    """
    from desktop import bootstrap

    log_path = bootstrap.prepare()
    # prepare 之后才 import:下面这几个会连带拉进 settings.config / tools.sandbox,
    # 而它们的模块级常量/单例必须在环境注入之后才求值
    from desktop import preflight, server, shutdown

    print(f"[smoke] 日志:{log_path or '(未启用,当前有控制台)'}")
    result = preflight.run()
    if not result.ok:
        print(f"[smoke] 预检未通过:{result.title} / {result.detail} / {result.hint}")
        return 2
    srv = server.Server()
    srv.start()
    if not srv.wait_ready():
        print("[smoke] 服务未就绪:根路径没有返回页面,检查前端产物是否打进了包")
        shutdown.finish(srv, 3)
    print(f"[smoke] 就绪:{srv.url}")
    shutdown.finish(srv, 0)
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```
