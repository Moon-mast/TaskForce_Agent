# desktop_0.1 总览:把 TaskForce 打包成 Windows 桌面应用

> 状态:方案已定,按 [TODO.md](TODO.md) 推进 | ADR:[0013-desktop-shell](../../adr/0013-desktop-shell.md)
> 一句话:用 **pywebview 单窗口 + PyInstaller onedir 全量冻结**,让 TaskForce 从「四条命令起步」变成「双击即用」。

## 1. 为什么做

现状起步需要四步:`docker compose up -d` 起 PostgreSQL、`cd dev/front && npm install && npm run build`
出前端产物、`uv run uvicorn api.main:app --port 8010` 起服务、再用浏览器打开 `127.0.0.1:8010`。
对开发者没问题,但作为**交付物**不合格——拿到项目的人要装 uv、Python 3.12、Node、Docker。

目标:一个原生窗口承载现有 Vue 工作台,后端在同进程内起,配置/技能/会话状态落到用户目录而非仓库。

## 2. 四个已定决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 壳 | **pywebview 单窗口** | 项目已有「FastAPI 同源托管 dist」形态(`api/main.py:36`),壳只要指向 `127.0.0.1:8010`。不引入 Node/Rust 第二套壳 |
| 外部依赖 | **保持外部**(PG 走 docker 5433、Milvus 走 WSL 19530) | 不内嵌、不降级功能;启动器负责把「服务没起」翻译成中文提示 |
| 冻结 | **PyInstaller onedir 全量**(含 docling/torch) | 换 PDF/docx 解析开箱可用,接受 2-3GB。onedir 避免 onefile 每次启动解包 GB 级 |
| 节奏 | **两阶段**:先不冻结跑通壳,再上 PyInstaller | 冻结失败时能立刻判断是路径层的错还是打包配置的错 |

## 3. 问题的真正难点:不是壳,是路径

全仓有 **11 处路径锚点**在冻结后失效,其中三处**静默出错不报错**。这张表就是改动清单:

| # | 锚点 | 冻结后症状 |
|---|---|---|
| 1 | `settings/config.py:25` `parents[2]/.env` | 🔴 起不来(启动前提) |
| 2 | `agent/memory_ctx.py:34` **裸 `Path("BACKEND.md")`** | 🔴 **静默降级成占位串**——产品人格背景整体丢失,不报错。最隐蔽 |
| 3 | `settings/loader.py:19` `resources.files("prompts")` | 🔴 缺 md 且无 try/except → 崩图 |
| 4 | `tools/skills/loader.py:20` `parents[3]/skills` | 🔴 技能系统整体失效 |
| 5 | `tools/mcp/config.py:8` `parents[3]/mcp_config.json` | 🔴 读+写;设置页「保存成功但重启就没了」 |
| 6 | `api/main.py:36` `parents[2]/dev/front/dist` | 🔴 静默跳过 mount → 白屏 |
| 7 | `settings/model_overrides.py:24` **裸 `.taskforce/`** | 🔴 随 CWD 漂移;只读目录则 500 |
| 8 | `settings/session.py:12` **裸 `.taskforce/`** | 🔴 同上,且 `mkdir` 缺 `parents=True` |
| 9 | `rag_v01/config.py:24` `RAG2_IMAGE_DIR` 默认 `data/rag2_images` | 🔴 图片块**静默退化成纯文本** |
| 10 | HF 模型缓存(**代码零配置**) | 🔴 首传 PDF 卡数分钟无提示,落 `~/.cache/huggingface` |
| 11 | `rag_v01/evaluation.py:31`、`rag_v01/load.py:22` | 🟢 排除出 bundle |

> #7 与 #8 是**同一个 `.taskforce/` 目录,裸常量写了两遍** → 收口到一处。

## 4. 解法:`settings/appdirs.py` 双态路径层

一个模块作为**所有运行时路径的唯一出处**,按 `sys.frozen` 分双态:

| 概念 | 开发态(**保持现状**) | 冻结态 |
|---|---|---|
| `data_root()` | 仓库根 | `%LOCALAPPDATA%\TaskForce` |
| `bundle_root()` | 仓库根 | `sys._MEIPASS` |
| `static_dir()` | 仓库根 `dev/front/dist` | `_MEIPASS/web` |

**关键设计选择:开发态 `data_root()` 仍等于仓库根** → 全部调用点在开发态的取值与重构前
**逐字节相同**,479 条后端基线 + 185 条前端基线不受影响,改动可逐处 review。

`TASKFORCE_HOME` 环境变量作逃生口 + 单测 seam(测试指向 `tmp_path`,不必真冻结)。

`rag_v01` 保持**零改动**(它的定位是「独立可搬」,不能反向 import `settings`):
#9 / #10 由**启动器在 import 任何 app 模块之前注入环境变量**解决。

详见 [01-路径层重构.md](01-路径层重构.md)。

## 5. 桌面壳:`src/desktop/`(第 8 个包)

按项目既有逻辑「一个入口一个包」(cli=终端、api=HTTP),桌面壳是第三个入口。

六个文件:`bootstrap`(环境注入 + stdout 落日志)、`preflight`(配置/PG/Milvus 预检)、
`setup_window`(统一故障窗口)、`server`(uvicorn 后台线程)、`shutdown`(分层退出)、
`app`(pywebview 窗口 + 编排)+ `__main__`(入口)。

四个**必须显式给、否则静默出错**的点:

| 点 | 不做的后果 |
|---|---|
| `gui="edgechromium"` | 回落 IE11 → dist 是 es2022 目标 → **白屏** |
| `private_mode=False` | pywebview 默认为 True → **每次退出清空 localStorage**,会话/view 每次都忘 |
| `sys.stdout` shim | windowed 下 `print(..., file=sys.stderr)` **静默 no-op** → 任务异常/技能跳过等诊断全灭 |
| 就绪轮询打 `GET /` 而非 `/health` | `/health` 会**真建云沙箱并计费** |

详见 [02-桌面壳.md](02-桌面壳.md)。

`build/TaskForce.spec`(windowed)+ `TaskForce-debug.spec`(console)+ `build/build.ps1`。

## 7. 被否掉的替代方案

| 方案 | 否决理由 |
|---|---|
| **启动时 `os.chdir(data_root)`** | 能解决 #2/#7/#8/#9 这些**裸 CWD 相对路径**,看似省事。但解决不了 #1/#4/#5/#6 那些 **`__file__` 锚定**的锚点,两套机制并存比一套更糟;且 chdir 会改变用户传入相对路径(如 `rag_v01 ingest <路径>`)的解析基准,副作用外溢 |
| **内嵌 PostgreSQL + 砍掉 Milvus** | Milvus 没有 Windows 版 Lite,知识库必然降级;且嵌入式 PG 与现有 `database_url` 配置/迁移逻辑要重新设计 |
| **Electron / Tauri 壳** | 都要引入第二套语言栈(Electron 多一套 Node 壳;Tauri 要装 Rust + MSVC)。本项目后端已是 Python、前端已同源托管,pywebview 直接复用,收益不抵成本 |
| **onefile 单 exe** | 2-3GB 每次启动都要解压到临时目录,首启十几秒到一分钟,且体积大时崩溃率更高 |
| **端口占用则顺延** | 前端把会话 id 等状态存在 `localStorage`,**按 origin 隔离**——端口一变等于换了个应用,每次启动丢状态 |

## 8. 已知风险(诚实说明)

PyInstaller 全量冻结 docling + torch **没有银弹**,`hiddenimports` 需要实测迭代。
两阶段推进就是为了让失败可定位:阶段 1 跑通了,阶段 2 的问题就只可能在打包配置里。

`rag_v01` 的子模块**全部是函数体内懒 import**(`rag_v01/__init__.py:9-10`),
依赖图看不见它们 → 必须手写 hiddenimports,漏了要等**第一次上传文件**才炸。

若 hiddenimports 反复不通过,退回选项是排除 docling(知识库上传降级)——那会推翻「全量冻结」,
届时再议。
