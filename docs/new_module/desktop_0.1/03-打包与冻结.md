# 03 打包与冻结(PyInstaller onedir)

> 前置:[01 路径层](01-路径层重构.md) + [02 桌面壳](02-桌面壳.md) 都已落地并能 `uv run python -m desktop` 跑通。
> **顺序不能颠倒**:先在不冻结的状态下把壳跑通,再上 PyInstaller。否则冻结一失败,你分不清
> 是路径层的错还是打包配置的错 —— 这正是本方案分两阶段的全部意义。

## 1. 产物与命令

脚手架在 `packaging/`(**不叫 `build/`** —— 那在 `.gitignore` 里,spec 会入不了库):

| 文件 | 作用 |
|---|---|
| `packaging/TaskForce.spec` | 一个 spec,经环境变量产两个变体 |
| `packaging/build.ps1` | 驱动脚本:前端构建 → `uv sync --frozen` → 跑两遍 pyinstaller |

```powershell
powershell -ExecutionPolicy Bypass -File packaging/build.ps1
# 已出过前端产物时跳过第一步(省几分钟)
powershell -ExecutionPolicy Bypass -File packaging/build.ps1 -SkipFront
# 只出 console 变体(排障时的常用姿势)
powershell -ExecutionPolicy Bypass -File packaging/build.ps1 -SkipFront -Only debug
```

产物:

```
dist/release/TaskForce/TaskForce.exe             ← 交付用(windowed,双击即用)
dist/debug/TaskForce-debug/TaskForce-debug.exe   ← 排障用(带控制台)
```

**两个变体不是冗余**:windowed 下 `sys.stdout` 是 `None`,**任何输出都看不见** ——
console 变体是唯一的排障入口,也是 `--tf-smoke` 自检要看输出的那个。

**交付时整个文件夹一起给**:只拷 exe 必然失败,同级 `_internal/` 里是全部依赖。

## 2. spec 的结构与"改一处要改两处"的对应关系

spec 里 `datas` 的每个 `dest` 都**必须与 `settings/appdirs.py` 里对应函数的冻结态返回值逐字对应**。
对不上不会在构建期报错,只会运行时 `FileNotFoundError` 或白屏:

| `appdirs` 函数 | 冻结态返回 | spec 的 datas 源 → dest |
|---|---|---|
| `static_dir()` | `_MEIPASS/web` | `dev/front/dist` → `web` |
| `prompts_dir()` | `_MEIPASS/prompts` | `src/prompts` → `prompts` |
| `_bundle_skills_dir()` | `_MEIPASS/default_skills` | `skills` → `default_skills` |
| `backend_md_path()` 回落 | `_MEIPASS/BACKEND.md` | `BACKEND.md` → `.` |
| `_seed_env()` 模板 | `_MEIPASS/.env.example` | `.env.example` → `.` |

> 源是**目录**时,PyInstaller 把目录**内容**拷进 dest —— 所以 `src/prompts` → `prompts` 得到的是
> `_MEIPASS/prompts/*.md`,而不是 `_MEIPASS/prompts/prompts/`。

构建后**先核对这一步**,再谈其他:

```bash
ls dist/debug/TaskForce-debug/_internal/prompts/           # 期望:__init__.pyc + 8 个 md
ls dist/debug/TaskForce-debug/_internal/prompts/subagents/ # 期望:3 个 md
ls dist/debug/TaskForce-debug/_internal/web/               # 期望:index.html + assets/
ls dist/debug/TaskForce-debug/_internal/default_skills/    # 期望:hello-world 等
```

## 3. 为什么 hiddenimports 必须手写(最可能反复的一步)

`rag_v01` 承诺「无 import 副作用:不加载 docling / pymilvus / sentence-transformers」,
于是它的子模块**全部在函数体内按需 import**。PyInstaller 走静态依赖图,看不见它们。

**漏掉的后果是最难查的一类**:构建成功 → 启动正常 → 界面正常 → **第一次上传文件**
才 `ModuleNotFoundError: pymilvus`。

spec 里用 `collect_submodules` 把本项目七个包(除 `cli`)的子模块全收进来,从根上绕开这个问题;
再补一份第三方显式清单(动态 import / 插件式加载的那些)。

> ⚠️ 收集时要 `filter` 掉 `tools/sandbox/test/`:那里的 `tencent_test.py` 会连真实 e2b,
> 收进来会让**构建期**去 import 它(实测直接抛 `AuthenticationError`,整次构建失败)。

**迭代姿势**:冻结产物跑到某个功能报 `ModuleNotFoundError` 时,把那个模块名加进 spec 的
`hiddenimports` 再重建。这是本 spec 唯一需要反复调的地方。

## 4. 为什么冻结脚本必须 `uv sync --frozen`

`pyproject.toml` 里 `docling>=2.128.0` **没有上界**。不加 `--frozen` 的话,某次重跑会解析出
完全不同的依赖树 —— 而你会以为是 spec 写错了,排查方向从一开始就错了。`uv.lock` 已在仓库里,
锁住它。

## 5. 验收

### 5.1 无窗口自检(先跑这个,再双击)

```powershell
dist\debug\TaskForce-debug\TaskForce-debug.exe --tf-smoke
```

退出码即结论:`0` 正常 / `2` 预检未通过 / `3` 服务未就绪(多半是前端产物没打进去)。
期望输出末尾是 `[smoke] 就绪:http://127.0.0.1:8010/`。

这一步的价值:**在命令行里就能验证冻结产物**,不必靠"点开窗口看一眼"。

### 5.2 逐项验收

| 验什么 | 怎么验 | 若失败,先怀疑 |
|---|---|---|
| 窗口起来 | 双击 `TaskForce.exe` | `gui="edgechromium"` 有没有给(不给会落 IE11) |
| 界面可用 | 看到工作台而非白屏 | `_internal/web/` 里有没有 index.html |
| 后端在跑 | 发一轮对话有回复 | 壳与 uvicorn 的编排 |
| 提示词在 | 对话不崩 | `_internal/prompts/` 里的 8 个 md |
| **人格背景在** | 问一个只有 `BACKEND.md` 里才有的事实 | `_internal/BACKEND.md`。**这条不验就永远是静默的** |
| 技能在 | 设置页技能列表非空 | `_internal/default_skills/` + 首启播种 |
| **配置落对地方** | 设置页改模型配置 → 重启 → 仍生效 | `%LOCALAPPDATA%\TaskForce\.taskforce\` |
| **localStorage 没被清** | 关窗重开,上次会话还在 | `private_mode=False` 有没有给 |
| 数据目录 | `%LOCALAPPDATA%\TaskForce\` 下有 `.env`/`skills/`/`.taskforce/`/`logs/` | `ensure_data_layout()` |
| 知识库 | 上传一个 docx → 检索到 | hiddenimports + `.env` 里的 `RAG2_*` |
| **关窗干净退出** | 关窗后任务管理器无残留 | 退出序列走到 `os._exit` 了吗 |
| **沙箱被回收** | 关窗后云端无残留实例 | `shutdown()` 有没有真被调(不调就漏计费) |
| 无诊断黑洞 | `logs/desktop.log` 有内容 | stdout shim 装上了吗 |

### 5.3 故障注入(比顺利路径更重要)

桌面应用的成本 90% 在失败路径上。逐条注入,确认都给中文提示而不是白屏/闪退:

1. 不起 PostgreSQL → 「PostgreSQL 连不上」+ `docker compose up -d` 指引
2. 删掉 `.env` → 重新播种 + 中文报错(不是 pydantic 堆栈)
3. `.env` 里 LLM key 留空 → 点「打开配置文件」填完 → 点「重试」**真的生效**
4. 不起 Milvus → 启动不阻塞、能对话;知识库页给错误提示
5. 先手动占住 8010 → 「端口 8010 已被占用」+ 指引(不是 WinError 10048 静默死)
6. 关窗时有任务在跑 → 有界退出,不挂几分钟

## 6. 已知取舍与未解风险

**取舍**:`shutdown.finish()` 最后的 `os._exit` 会**丢弃正在执行的子图任务**。
若关闭时正好有计划在推进,那个步骤会停在 running,下次启动不自动续跑。
与 REPL 里 Ctrl+C 的后果一致,是既有设计,本期不引入断点续跑。
(这也是为什么 `tools/sandbox/client.py` 的回收要先显式调 —— `os._exit` 会跳过 `atexit`。)

**未解风险**:全量冻结 docling + torch **没有银弹**。本机首次构建体量在 2-3GB 量级、
耗时较长,hiddenimports 可能要来回几轮。若长期不通过,退回选项是**排除 docling**
(代价:知识库上传解析不可用,只剩检索已有语料)—— 那会推翻「全量冻结」的决策,届时再议。
