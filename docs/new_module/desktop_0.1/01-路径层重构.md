# 01 路径层重构:`settings/appdirs.py`

> 这一步是**桌面壳的前置**。不改路径层就上 PyInstaller,会得到一堆静默失效。
> 验收:`uv run pytest -q` 仍 **479 绿**(证明开发态零变化)+ `tests/test_appdirs.py` 绿。

## 1. 设计要点

**双态**:按 `sys.frozen` 分开发态与冻结态。**开发态的取值与重构前逐字节相同** —— 这是本方案
最重要的安全属性:479 条后端基线不受影响,每一处改动都可以单独 review。

| 概念 | 开发态 | 冻结态 |
|---|---|---|
| `data_root()` | 仓库根 | `%LOCALAPPDATA%\TaskForce` |
| `bundle_root()` | 仓库根 | `sys._MEIPASS` |
| `static_dir()` | 仓库根 `dev/front/dist` | `_MEIPASS/web` |

**`TASKFORCE_HOME` 优先于两者**:既是部署逃生口(用户可把数据目录指到别处),也是单测 seam
(测试指向 `tmp_path`,不必真的冻结)。

**为什么不用 `os.chdir(data_root)`**:它能解决裸 CWD 相对路径,但解决不了 `__file__` 锚定的那些,
两套机制并存比一套更糟;且会改变用户传入相对路径的解析基准。见 ADR-0013 被否方案。

## 2. 新建 `src/settings/appdirs.py`

放在 `settings/` 而不是 `tools/`,因为它是**基础设施**(与 config / db / session 同级),
且 `tools` 依赖 `settings` 的方向是既定的,放这里不会引入新的依赖方向。

```python
"""应用路径解析单一事实源:开发态与冻结态(PyInstaller)双态,消除 CWD 与 __file__ 上溯依赖。

本文件作用:
    全仓运行时路径的唯一出处。**开发态返回仓库根下的既有位置(与重构前逐字节相同)**,
    冻结态切到 %LOCALAPPDATA%\\TaskForce 与 PyInstaller 解包目录。
    ensure_data_layout() 负责首启建目录,并从只读资源播种 skills/ 与 .env。

使用位置:
    - settings/config.py:.env 路径;
    - settings/session.py、settings/model_overrides.py:.taskforce 状态目录;
    - settings/loader.py:prompts/ 提示词目录;
    - tools/skills/loader.py:技能根目录;
    - tools/mcp/config.py:mcp_config.json 路径;
    - api/main.py:前端构建产物目录;
    - agent/memory_ctx.py:BACKEND.md 路径;
    - desktop/bootstrap.py:环境变量注入与首启播种。
"""
import os
import shutil
import sys
from pathlib import Path

APP_NAME = "TaskForce"

# 可写数据根的环境变量名:既是部署逃生口(指到任意目录),也是单测 seam
HOME_ENV = "TASKFORCE_HOME"

# 播种 .env 时清空取值的三个键。理由见 _seed_env:让启动落到 assert_ready 的现成中文报错上,
# 而不是带着 "sk-your-llm-api-key" 这种模板假值启动、到第一次调用模型才报 401
BLANK_ON_SEED = ("LLM_BASE_URL", "LLM_API_KEY", "LLM_MODEL")


def is_frozen() -> bool:
    """是否运行在 PyInstaller 冻结产物里。"""
    return bool(getattr(sys, "frozen", False))


def bundle_root() -> Path:
    """只读资源根:冻结态是解包目录 sys._MEIPASS,开发态是仓库根。"""
    if is_frozen():
        return Path(sys._MEIPASS)
    return Path(__file__).resolve().parents[2]


def data_root() -> Path:
    """可写数据根:开发态=仓库根(保持既有行为),冻结态=%LOCALAPPDATA%/TaskForce。"""
    override = os.environ.get(HOME_ENV)
    if override:
        return Path(override)
    if is_frozen():
        local = os.environ.get("LOCALAPPDATA") or (Path.home() / "AppData" / "Local")
        return Path(local) / APP_NAME
    return bundle_root()


def env_file() -> Path:
    """Settings 读的 .env;冻结态首启由 ensure_data_layout() 从 .env.example 播种。"""
    return data_root() / ".env"


def state_dir() -> Path:
    """本地运行状态目录 .taskforce/(会话 id、模型覆盖表)。

    重构前这个目录在 session.py 与 model_overrides.py 里各写了一遍裸相对路径,
    统一收口到本函数。
    """
    return data_root() / ".taskforce"


def skills_dir() -> Path:
    """技能根目录(SkillRegistry 扫描的一级子目录)。"""
    return data_root() / "skills"


def mcp_config_path() -> Path:
    """MCP 服务器配置(读+写双向下)。"""
    return data_root() / "mcp_config.json"


def prompts_dir() -> Path:
    """提示词 md 目录。

    改读**磁盘路径**而非 importlib.resources:后者的可用性依赖包解析与 zip 语义
    (包能否 import、md 是否落在真实目录而非 base_library.zip、__init__ 与 md 是否同目录),
    冻结下任一不满足就 FileNotFoundError。磁盘路径只依赖"文件在不在"。
    """
    if is_frozen():
        return bundle_root() / "prompts"
    return bundle_root() / "src" / "prompts"


def backend_md_path() -> Path:
    """产品运行时背景 BACKEND.md:用户数据目录优先(便于自定义),否则回落包内。"""
    custom = data_root() / "BACKEND.md"
    if custom.is_file():
        return custom
    return bundle_root() / "BACKEND.md"


def static_dir() -> Path:
    """前端构建产物目录,由 api/main.py 挂到根路径。"""
    if is_frozen():
        return bundle_root() / "web"
    return bundle_root() / "dev" / "front" / "dist"


def ensure_data_layout() -> None:
    """首启准备:建可写目录,并从只读资源播种 skills/ 与 .env。

    幂等,且**已存在的文件一律不覆盖** —— 用户的 .env 与自装技能必须保住。
    """
    for directory in (data_root(), state_dir(), skills_dir()):
        directory.mkdir(parents=True, exist_ok=True)
    _seed_skills()
    _seed_env()


def _bundle_skills_dir() -> Path:
    """包内默认技能目录(只读);冻结态由 spec 收集到 _MEIPASS/default_skills。"""
    if is_frozen():
        return bundle_root() / "default_skills"
    return bundle_root() / "skills"


def _seed_skills() -> None:
    """把包内默认技能补齐到可写目录;同名目录已存在则整体跳过。"""
    source = _bundle_skills_dir()
    if not source.is_dir():
        return
    target = skills_dir()
    for child in source.iterdir():
        if not child.is_dir():
            continue
        dest = target / child.name
        if dest.exists():
            continue
        shutil.copytree(child, dest)


def _seed_env() -> None:
    """从 .env.example 播种 .env,并把 BLANK_ON_SEED 三个键的取值清空。

    DATABASE_URL 在模板里已是 docker-compose 的默认值,照抄即可;
    LLM 三项清空后,get_settings() 会落到 assert_ready 的现成中文报错
    「配置缺失,请在 .env 中填写以下变量:...」—— 预检窗口原样展示这句话即可,零新增表单。
    """
    target = env_file()
    if target.is_file():
        return
    template = bundle_root() / ".env.example"
    if not template.is_file():
        return
    lines = []
    for line in template.read_text(encoding="utf-8").splitlines():
        key = line.split("=", 1)[0].strip()
        if key in BLANK_ON_SEED:
            lines.append(f"{key}=")
        else:
            lines.append(line)
    target.write_text("\n".join(lines) + "\n", encoding="utf-8")
```

> 注:`line.split("=", 1)[0].strip()` 对注释行(`# LLM_BASE_URL=...`)得到的是 `# LLM_BASE_URL`,
> 不在 `BLANK_ON_SEED` 里,所以注释照常保留 —— 不需要额外的注释判断。

### 3.3 `src/settings/loader.py` —— 提示词目录(#3)

整体改完是这样:

```python
"""提示词加载器:prompts/ 数据包的唯一读取口(零代码 md + $ 占位符渲染)。

使用位置:
    - agent/supervisor.py:load_prompt("supervisor");
    - agent/answer.py:load_prompt("answer");
    - agent/subagents/retriever.py:load_prompt("base") + load_prompt("subagents/retriever")。
"""
from string import Template

from settings.appdirs import prompts_dir


def load_prompt(name:str,**slots:str)->str:
    """
    读 prompts/<name>.md 并渲染 $ 占位符。
    例:load_prompt("supervisor", agents_md="...", memory="...")
    占位符必须用 $name 形式(string.Template):提示词内含 JSON 花括号,
    str.format 会崩;缺失插槽 Template.substitute 直接 KeyError,符合预期。

    路径经 appdirs.prompts_dir() 解析:开发态是 src/prompts/,冻结态是包内 prompts/。
    """
    text=(prompts_dir()/f"{name}.md").read_text(encoding="utf-8")
    return Template(text).substitute(**slots)
```

**注意两点**:
- `importlib.resources` 的 import 要删掉(不再使用)。
- 本文件是**存量风格**(无空格 `name:str`,见 `docs/dev/style-violations-20260925.md`)。
  按「谁改到谁顺手改」,你改到这里时把它顺手规范成悬挂缩进 + 尾逗号;上面给的是**最小改动版**,
  想一并规整就按 `python-camel-style` 写。

> **副作用**:`load_prompt` 依然**没有 try/except** —— md 缺失仍然直接崩。这是既有设计
> (提示词缺失属于部署事故,不该静默降级),本次不改。变的是"路径不会因为冻结而失效"。

### 3.8 `src/tools/sandbox/client.py` —— 抽出公开的 `shutdown()`

现在云沙箱回收只靠 `atexit.register(_kill)`(第 90 行)。桌面壳的退出兜底走 `os._exit`,
**会跳过全部 atexit** → 云沙箱漏回收,按存活时长计费(`SANDBOX_TTL=3600`,最长空转 1 小时)。
所以把回收变成可显式调用的公开函数:

```python
def shutdown() -> None:
    """显式回收云端沙箱实例。

    公开出来是给桌面壳的退出序列用:退出兜底走 os._exit 会跳过 atexit,
    不先显式调一次就会漏回收并继续计费。重复调用安全。
    """
    _kill()


atexit.register(_kill)   # 保留:非桌面入口(CLI/API)仍靠它兜底
```

## 4. `rag_v01` 零改动(可搬性红线)

`rag_v01` 的定位是「独立可搬」(AGENTS.md),**不能反向 import `settings`**。它的 `config.py`
明确写了「本文件不读 .env 文件 —— 载入由入口负责」,只认**进程环境变量**。
所以 #9(`RAG2_IMAGE_DIR`)与 #10(`HF_HOME`)不由它改,由桌面壳的 bootstrap 注入(见 02 篇)。

**这带来一个必须补的缺口**:`.env.example` 目前**全文没有任何 `RAG2_*`**,而 `rag_v01` 的上传/检索
需要它们(缺 `RAG2_EMBED_API_KEY` 时 `rag_v01/embed.py` 直接抛
`ValueError: RAG2_EMBED_MODE=api 需要 RAG2_EMBED_API_KEY`)。给 `.env.example` 补一段:

```dotenv
# ── 知识库(rag_v01):向量化与 Milvus 连接 ──────────────────────
# rag_v01 只认 RAG2_ 前缀的**进程环境变量**,不读 .env 解析器(见 rag_v01/config.py 头部说明),
# 所以桌面壳启动时会把整份 .env 载入进程环境,这一段才能生效。
# 变量名 = RAG2_ + rag_v01/config.py 里 Config 字段名大写(机械映射)。
RAG2_EMBED_MODE=api
RAG2_EMBED_MODEL=qwen3-vl-embedding
RAG2_EMBED_API_BASE=https://dashscope.aliyuncs.com/api/v1
RAG2_EMBED_API_KEY=your-embedding-api-key
RAG2_MILVUS_URI=http://localhost:19530
# 以下两项留空即可:默认值是 data/rag2_images(开发态相对 CWD,冻结态会失效);
# 桌面壳启动时会把它们显式指到用户数据目录,不依赖这里的取值
# RAG2_IMAGE_DIR=
# HF_HOME=
```

> 字段名已按 `src/rag_v01/config.py` 的实际声明核对过(注意是 `RAG2_EMBED_API_BASE` 而不是
> `..._BASE_URL`;`RAG2_EMBED_MODEL` 与 `..._API_BASE` 有默认值,理论上可以不填,但显式写出来更清楚)。
> 新增变量时只改 `rag_v01/config.py` + 该模块 01 篇变量表两处(见那个文件的头部注释)。
