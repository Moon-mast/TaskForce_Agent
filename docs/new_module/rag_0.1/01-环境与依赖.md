# 01-环境与依赖

> 本篇是 rag_0.1 的地基:Python 依赖、Milvus 服务(WSL docker)、多模态 embedding(阿里云百炼 `qwen3-vl-embedding`)、RAG2_ 环境变量、以及装完后的冒烟检查清单。本篇只产出文档,下面的 pyproject / docker-compose / .env 片段均为**说明性片段**,由落地阶段照抄使用,本文撰写过程不创建、不修改任何配置文件。

## 一、模块目标与边界

### 1.1 目标

把 `src/rag_v01/` 跑起来所需的**全部外部条件**一次配齐,配到"第五节冒烟清单全绿"为止:

1. **Python 依赖**:docling(解析)、pymilvus(向量库客户端)、ragas(评估)、langchain-openai(judge 与 embedding API 客户端)、rank_bm25 + jieba(BM25 备胎)、pytest(单测);sentence-transformers 仅在切 local 备选模式时才需要,列为可选;
2. **Milvus 服务**:部署在 **WSL 发行版内的 docker**(与现有 pgvector 同一套 docker 环境),起 standalone 并把客户端端口 19530 暴露给宿主(与 PostgreSQL 5433 并存);
3. **Embedding(定稿)**:阿里云百炼 `qwen3-vl-embedding`(多模态,文本与图片同一向量空间),DashScope SDK 调用,维度指定 1024;
4. **环境变量**:全部 `RAG2_` 前缀,追加进 `.env`,不动任何旧变量;
5. **验收**:逐条可执行的冒烟检查。

### 1.2 边界(不做什么)

- **不碰旧系统**:不改 `src/tools/rag/`、`docs/improved/`、现有 docker-compose(PostgreSQL 那份)、`.env` 里旧变量;
- **零项目依赖**:新模块不 import `agent/`、`tools/`、`settings/` 任何包,依赖清单只进 pyproject,不进任何业务代码;
- **全同步**:不装任何依赖 async 生态的包(如 asyncpg 类),后续 `store.py`/`retrieve.py` 全部用 pymilvus 的同步 API;
- **不管业务**:切块参数、索引参数的具体语义分别在 [./03-父子分块策略.md](./03-父子分块策略.md) 与 [./04-嵌入与Milvus索引.md](./04-嵌入与Milvus索引.md) 展开,本篇只负责"这些参数通过哪个环境变量注入"。

## 二、设计决策与理由(含备选对比)

### 2.1 依赖总表

| 包 | 版本约束 | 用途 | 约束理由 |
|---|---|---|---|
| `docling` | `>=2.30,<3` | pdf/docx/md 统一解析 | 2.x 线 `DocumentConverter`/`DoclingDocument` API 面稳定;迭代极快(2026-09 已到 2.124.0),靠 uv.lock 锁死具体版本,02 篇以锁定版实测为准 |
| `pymilvus` | `>=2.5` | Milvus 客户端 | **2.5 才引入 `Function`(FunctionType.BM25)与 collection 级自定义 analyzer**——children 表的 sparse 向量与 jieba 分词全靠它,这是硬下限 |
| `sentence-transformers` | `>=3` | **可选**:本地 embedding 备选路径 | 独立放 `rag2-local` extra,默认不装;定稿走 API(百炼),只有切 `RAG2_EMBED_MODE=local` 离线兜底时才需要;3.x 起 `SentenceTransformer.encode` API 稳定,BGE-M3 属 XLM-R 架构加载无障碍 |
| `ragas` | **暂未入 extra**(见 §4.5 坑位 10) | RAG 量化评估 | 实测冲突(2026-09-20): `ragas>=0.4` 经 instructor 依赖 `rich<15`,与主项目 `rich>=15.0.0` 互斥;能解析的 `ragas==0.3.1` 又因 `langchain_community.chat_models.vertexai` 已从 langchain-community 0.4 移除而 `import ragas` 直接报错。评估环境需与主环境隔离(方案见 [./06-ragas评估.md](./06-ragas评估.md) 坑位 2) |
| `langchain-openai` | `>=0.2` | judge(豆包,OpenAI 兼容) | `ChatOpenAI(base_url=...)` 指火山方舟;ragas 的 judge 需包成 LangchainLLMWrapper;embedding 不再走它 |
| `dashscope` | (随 uv.lock 锁最新) | **多模态 embedding 客户端** | `qwen3-vl-embedding` 的图片输入在 OpenAI 兼容端点上不可用,必须走 `dashscope.MultiModalEmbedding.call` |
| `rank_bm25` | `>=0.27` | 客户端 BM25 备胎 | 若 Milvus 端 BM25 Function/jieba analyzer 实测异常,进程内自算 BM25 兜底(见 04/05 篇风险注记) |
| `jieba` | `>=0.42` | 中文分词 | 备胎 BM25 的分词器,与 Milvus jieba analyzer 同源,保证两路可对照 |
| `pytest` | `>=8` | 单测 | 项目已有,列此仅为清单完整 |

**torch 体积与首次模型下载(重要预期管理)**:docling 依赖 PyTorch,Windows 下从 PyPI 默认装 CPU 轮子,加上依赖合计 **GB 级下载**(选 API 模式后 sentence-transformers 与 BGE-M3 权重都可不装/不下,但 docling 的 torch 省不掉);首次运行 docling 还会**联网下载版面识别/表格结构识别模型**(数百 MB,落 HuggingFace 缓存,受 `HF_ENDPOINT` 影响,见 2.5)。首次 `uv sync --extra rag2` + 首次解析各需数分钟到十几分钟,属正常,不是卡死。

### 2.2 解析层选型:docling vs 手拼三件套

备选是 `pypdf + python-docx + markdown` 各解析各的再手工归一。否决理由:三种格式各自的数据结构差异大(pypdf 只有坐标文本、python-docx 是 XML 树、md 是纯文本),手工归一到"结构树"等于自研半个 docling;而本方案的核心前提——**按标题层级边界做父块切分**——依赖统一的结构树,docling 的 `DoclingDocument`(含 `heading` 层级、`table`、`picture` 节点)正是为此而生。docling 代价是 torch 体积,换三格式一套结构树,值。

### 2.3 向量库客户端下限与备胎

pymilvus>=2.5 不是随手写的:children 表设计是 **text 字段挂 Milvus 内置 BM25 Function 生成 sparse 向量 + analyzer 配 jieba**,两者都是 2.5 起的服务端能力(详见 [./04-嵌入与Milvus索引.md](./04-嵌入与Milvus索引.md))。**风险注记(全局定稿口径)**:milvus-lite 及低版本下 BM25 Function 与 jieba analyzer 的支持情况需实测,若异常,备胎方案是进程内 rank_bm25 + jieba 客户端自算 BM25——所以这两个包**必须随主依赖装上**,不是可选件。

### 2.4 Milvus 部署形态:WSL docker standalone vs milvus-lite

milvus-lite(嵌入式,`MilvusClient("./local.db")`)最省事,但**官方不支持 Windows**——开发机是 Windows,直接出局。故统一用 docker compose 起 **Milvus standalone**(三容器:etcd + minio + standalone,客户端端口 **19530**)。

**部署位置(定稿):WSL 发行版内的 docker**——与现有 pgvector 同一套 docker 环境,宿主(Windows)侧的 uv 工程通过暴露的 19530 端口访问(WSL2 默认开启 localhost 转发,`http://localhost:19530` 与访问本地服务无异;配了 mirrored 网络同样成立),即"服务跑在 WSL、接口对宿主暴露"。要点:

- **compose 文件与数据卷都放 WSL 的 ext4 路径**(如 `~/milvus/`),不要挂 `/mnt/f` 之类 Windows 盘:跨文件系统 IO 慢一个量级,权限位也容易乱;
- **内存**:standalone 建议至少 4GB 可用内存,不足时它在 WSL 里反复重启(表现为 19530 连不上);宿主内存吃紧时在 `%UserProfile%\.wslconfig` 调 `memory=8GB`;
- 与 pgvector 的 compose **相互独立**(推荐独立文件,便于单独开关与排错),端口 19530/9091 与 pg 的 5433 不冲突;
- 三个容器都加 `restart: unless-stopped`,WSL/docker 重启后自动拉起。

服务端版本取 **2.6.x 稳定线**(满足定稿的"Milvus 2.5+");Milvus 3.0(2026-07 stable)官方声明不保证与 2.x 客户端兼容,且 BM25/analyzer 并非其增量卖点,**不追新**。

### 2.5 Embedding:百炼 `qwen3-vl-embedding`(多模态,定稿) vs 本地 bge-m3(纯文本离线备选)

**定稿:API 模式,模型 `qwen3-vl-embedding`(阿里云百炼)**——多模态向量模型,文本与图片映射到**同一向量空间**,因此 02 篇抽取的图片不再只是"占位文字",而是以真向量进入 dense 路,文本 query 可以直接跨模态命中图片块。官方接口事实(2026-09 核对):

- 输入:text(32,000 token,33 种语言)/ image(URL 或 Base64;JPEG/PNG/WEBP/BMP/TIFF 等)/ video(仅 URL);单次请求内容元素总数 ≤20、图片 ≤5、视频 ≤1;单图 ≤10MB;
- 调用方式:**DashScope SDK `dashscope.MultiModalEmbedding.call`**(或 HTTP),**OpenAI 兼容端点不支持图片输入**,所以 `rag2` extra 增加 `dashscope` 包;维度经 `dimension=1024(SDK 顶层参数)` 指定;
- 默认 2560 维,可选 2560/2048/1536/1024/768/512/256——**本期锁定 1024**,与 `dim=1024` 的 schema 对齐;
- 价格(华北2北京):图片/视频 1.8 元/百万 token,文本 0.7 元/百万 token;免费额度 100 万 token(90 天);限流 RPM 2400 / TPM 120 万。

| 维度 | API:`qwen3-vl-embedding`(定稿,多模态) | 本地:`BAAI/bge-m3`(离线备选,**仅文本**) |
|---|---|---|
| 图片块 | ✅ 真向量,跨模态检索成立 | ❌ 只能靠占位/VLM 描述文本参与 |
| 前置 | 一个百炼 API Key + `dashscope` 包 | torch + 约 2GB 模型下载 |
| 维度 | 指定 1024(默认 2560) | 1024 |
| 成本 | 图片 1.8 / 文本 0.7 元每百万 token | 一次性下载,之后免费 |

注意点:(a) 入库与查询必须同模型同模式,维度必须等于 children 表 `dim=1024`(04 篇双处硬校验);(b) local 模式不支持图片向量——切 local 时图片块退化为"占位/VLM 描述文本"参与检索,只适合纯文本语料的离线调试;(c) 图片与文本**融合向量**(`enable_fusion=true`,多图+文本合成 1 个向量)本期不用,列为后续优化。

**HF_ENDPOINT 镜像说明**:API 模式下该变量只影响 docling 首次下载解析模型;不需要本地模型时可不设,但 docling 的模型下载仍受它影响,直连不畅时仍建议设置。

## 四、实现要点

### 4.1 pyproject 追加(说明性片段)

依赖放 **optional-dependencies 组 `rag2`** 而非主依赖:torch + docling 合计 GB 级,主线 agent 开发没必要强制背上;装法 `uv sync --extra rag2`。**实测(2026-09-20)**: docling / rank_bm25 / jieba / langchain-openai / pytest 已在主依赖里,extra 实际只需兜 rag_0.1 独有的 **`dashscope` + `pymilvus`**;ragas 因依赖冲突暂缺(见 §4.5 坑位 10,方案见 06 篇坑位 2)。本地离线兜底另立 `rag2-local`(1 包),定稿 API 模式不需要它。

```toml
[project.optional-dependencies]
rag2 = [
  "dashscope",        # 多模态 embedding(MultiModalEmbedding; OpenAI 兼容端点不支持图片)
  "pymilvus>=2.5,<3", # Milvus 客户端; 3.x 客户端未与 2.6 服务端验证过,先钉 <3(BM25 Function/analyzer 仍需 2.5+)
]
# 仅切 local 离线备选模式时需要(定稿走 API, 默认不装):
rag2-local = ["sentence-transformers>=3"]
```

### 4.2 Milvus standalone compose(说明性片段)

建议独立成 `docker-compose.milvus.yml`,**放 WSL 内**(如 `~/milvus/`,数据卷随之落在 ext4 路径,不要挂 /mnt),`docker compose -f docker-compose.milvus.yml up -d` 启动,不与 PostgreSQL 那份互相触碰。etcd/minio 只在 compose 内网通信、不对宿主暴露端口,杜绝与宿主其他服务撞端口;standalone 暴露 **19530**(pymilvus 连它)与 9091(健康检查/指标)。三个容器都加 `restart: unless-stopped`,WSL/docker 重启自动拉起。

```yaml
services:
  etcd:
    container_name: milvus-etcd
    restart: unless-stopped
    image: quay.io/coreos/etcd:v3.5.18        # 官方蓝本同系列,可按官方 docker-compose.yml 对齐
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision
      - ETCD_AUTO_COMPACTION_RETENTION=1000
      - ETCD_QUOTA_BACKEND_BYTES=4294967296
    volumes:
      - ${DOCKER_VOLUME_DIRECTORY:-.}/volumes/etcd:/etcd-data
    command: etcd -advertise-client-urls=http://etcd:2379 -listen-client-urls http://0.0.0.0:2379 --data-dir /etcd-data

  minio:
    container_name: milvus-minio
    restart: unless-stopped
    image: minio/minio:RELEASE.2023-03-20T20-16-18Z   # 官方蓝本沿用多年的 tag
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    volumes:
      - ${DOCKER_VOLUME_DIRECTORY:-.}/volumes/minio:/minio_data
    command: minio server /minio_data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3

  standalone:
    container_name: milvus-standalone
    restart: unless-stopped
    image: milvusdb/milvus:v2.6.21           # 2.6.x 稳定线,满足定稿"Milvus 2.5+";不追 3.0
    command: ["milvus", "run", "standalone"]
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    volumes:
      - ${DOCKER_VOLUME_DIRECTORY:-.}/volumes/milvus:/var/lib/milvus
    ports:
      - "19530:19530"    # pymilvus 客户端端口
      - "9091:9091"      # healthz / metrics
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9091/healthz"]
      interval: 30s
      start_period: 90s
      timeout: 20s
      retries: 5
    depends_on:
      - etcd
      - minio

  attu:                                       # 可选:Web 可视化,浏览器 localhost:3000
    container_name: milvus-attu
    image: zilliz/attu:latest
    environment:
      MILVUS_URL: milvus-standalone:19530
    ports:
      - "3000:3000"
    depends_on:
      - standalone
```

### 4.3 本地备选模式的模型下载(定稿 API 模式可整节跳过)

定稿走百炼 API,**无任何模型下载**;以下仅在切 `RAG2_EMBED_MODE=local` 离线兜底时需要。先设镜像(建议写进系统环境变量或 `.env` 由启动脚本带上):

```bash
# PowerShell:$env:HF_ENDPOINT = "https://hf-mirror.com"
# 或 .env 内(由各入口加载后 export)
HF_ENDPOINT=https://hf-mirror.com
```

然后任意一次 `SentenceTransformer("BAAI/bge-m3")` 即完成下载缓存(约 2GB,落 `~/.cache/huggingface`)。

### 4.4 .env 追加段(说明性片段,只增不改)

```dotenv
# ---- rag_0.1(全部新增,不动上方旧变量)----
HF_ENDPOINT=https://hf-mirror.com          # 只影响 docling 首次下载解析模型; 不需要可删
RAG2_MILVUS_URI=http://localhost:19530
RAG2_EMBED_MODE=api
RAG2_EMBED_MODEL=qwen3-vl-embedding
RAG2_EMBED_API_BASE=https://dashscope.aliyuncs.com/api/v1
RAG2_EMBED_API_KEY=sk-<百炼 API Key>
RAG2_EMBED_DIM=1024
RAG2_EMBED_BATCH=20
RAG2_EMBED_IMG_BATCH=5
RAG2_JUDGE_API_BASE=https://ark.cn-beijing.volces.com/api/v3
```

**注意 `.env` 不会自动进 `os.environ`**:项目现有的载入机制在 `settings/config.py`(pydantic-settings 的 `env_file`),只对走该配置的代码生效;裸 `python -c` 冒烟命令必须显式带 `uv run --env-file .env python ...`(或在 PowerShell 里临时 `$env:RAG2_EMBED_API_KEY="sk-..."`)。新模块自己的 `config.py` 落地时同样要明确 `.env` 载入方式(见 [./07-接口设计与移植方案.md](./07-接口设计与移植方案.md))。

### 4.5 坑位清单

1. **milvus-lite 出局的原因要记牢**:不是"不好用",是官方不支持 Windows;文档教程里的 `MilvusClient("./milvus.db")` 写法在本机直接跑不了,别照抄。
2. **pymilvus 与 server 版本组合**:客户端 >=2.5 只是下限;若 `uv.lock` 解析出 2.6.x 客户端配 2.6.x server 最稳。BM25 Function + jieba analyzer 建表期才真正触发,**冒烟清单只验连接,该能力的实测在 04 篇验收**(全局定稿风险注记)。
3. **首次 docling 调用会"假死"**:在下载模型,受 `HF_ENDPOINT` 影响;没设镜像时可能长时间无输出后超时。可先用第五节的 embed 冒烟验证镜像连通,再跑解析。
4. **Windows GBK 坑**(项目已知):冒烟命令里打中文,用 `uv run python -X utf8 -c "..."` 或先 reconfigure stdout,否则 print 中文可能 UnicodeEncodeError。
5. **ragas 迭代快**:`ragas.metrics` 各指标 import 路径、`evaluate` 参数在 0.1→0.2 有破坏性变化,0.2+ 内部仍可能微调,06 篇落地时以锁版本实测 API 为准,不凭记忆写 import。
6. **9091 端口**:仅健康检查/指标用,被占用可从 ports 删掉该行,不影响 19530。
7. **attu 首次进会要求填 Milvus 地址**:compose 内已由 `MILVUS_URL: milvus-standalone:19530` 带出,直接用即可;Windows 侧浏览器开 `http://localhost:3000`(WSL 端口转发)。纯可选组件,坏了不阻塞主线。
8. **WSL 部署的两个常见坑**:数据卷不要落在 `/mnt/*`(Windows 盘)上,跨文件系统 IO 会让 Milvus 慢一个量级且权限位异常;WSL 内存不足时 standalone 反复重启(表现为 19530 连不上),先在 `.wslconfig` 给足内存再排其它。
9. **百炼多模态接口约定**:单请求内容元素总数 ≤20(其中**图片 ≤5**、视频 ≤1),文本/图片分别按 `RAG2_EMBED_BATCH` / `RAG2_EMBED_IMG_BATCH` 分批;维度经 `dimension=1024(SDK 顶层参数)` 指定(参数名是 `dimension`,默认 2560),改维度必须同步重建 collection;图片传 Base64 或公网 URL(本地落盘 PNG 转 `data:image/png;base64,...` 即可,不必自建图床),**单图 ≤10MB**。实测(dashscope 1.27.6): 维度必须作为顶层参数 `dimension=1024` 传入——写成 `parameters={"dimension":1024}` 会被静默忽略并返回默认 2560。
10. **ragas 装不进主环境(实测 2026-09-20)**: `ragas>=0.4` 经 instructor 钉 `rich<15`(0.4.2~1.8.3 更严,`<14`),与主项目 `rich>=15.0.0` 互斥,uv 直接报 unsatisfiable;降到唯一可解析的 `ragas==0.3.1` 又 `import` 即崩(`ragas/llms/base.py` 引 `langchain_community.chat_models.vertexai`,该模块已从 langchain-community 0.4 移除)。两条出路(06 篇落地时二选一): (a) 评估独立 venv(推荐,主环境零改动); (b) 主项目把 `rich` 放宽到 `<15` 再装(动主线依赖,须回归测试)。
11. **Milvus 落地两个实测坑**: (a) compose 文件名非默认名(`docker-compose.milvus.yml`)时**必须 `-f` 显式指定**,否则报 `no configuration file provided`; (b) Docker Hub 上 `minio/minio` 已取不到 tag,改用 `quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z`,且新版用 `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`(旧 `MINIO_ACCESS_KEY` 已废弃)。仓库根已有 `docker-compose.milvus.yml`,WSL 侧放 `~/milvus/`(=数据卷目录),三容器 healthy、客户端 19530 已连通(server 2.6.0)。
