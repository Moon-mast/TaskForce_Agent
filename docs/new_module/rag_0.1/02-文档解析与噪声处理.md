## 一、模块目标与边界

**目标**: 把 pdf / docx / md 三种文件统一解析成"结构化条目序列" `ParsedDoc`——每条带 `type`(text|table|image)、序列化文本、`heading_path` 标题面包屑、`page_no` 页码; 表格是整块 Markdown、图片落盘且有占位文本; 再清掉页眉页脚与文本噪声, 交给 03 篇做父子分块。

**边界(不做什么)**:

- 不切块([./03-父子分块策略.md](./03-父子分块策略.md))、不做 embedding 与入库([./04-嵌入与Milvus索引.md](./04-嵌入与Milvus索引.md))、不做检索([./05-混合检索与RRF融合.md](./05-混合检索与RRF融合.md))、不做评估([./06-ragas评估.md](./06-ragas评估.md));
- 不 import `agent/`、`tools/`、`settings/` 任何包; 全同步, 无 async/await; 配置只读 `RAG2_` 前缀;
- `.doc` / `.pptx` / `.html` 不在支持面: `.doc` 在入口直接报错并提示先转 `.docx`(不自动转换, 不引入 `soffice` 外部进程依赖);
- 图片语义描述与"扫描件全文 OCR"都是**可选开关, 默认关**——本模块不主动发起任何外部模型调用;
- 不做并发解析优化(全同步纪律): 大文件靠串行 + 进度日志, 见 4.7。

## 二、设计决策与理由(含备选对比)

### 2.1 三格式统一走 docling 的 `DocumentConverter`

| 备选 | 弃选理由 |
|---|---|
| pypdf / pdfplumber + python-docx + 自写 md 解析 | 三套数据模型要手工归一到"结构树"; pdf 天然没有标题层级、docx 天然没有页码, `heading_path` / `page_no` 只能靠正则猜; 表格靠启发式 |
| Unstructured | 结构标签粒度粗, 中文表格识别一般, 链路重 |
| Marker | 定位是"渲染成 Markdown", 拿不到可供切块决策的条目树 |
| **docling(选定)** | 一套 `DoclingDocument` 同时给出条目类型、标题层级、表格网格、图片、页码溯源(prov); PDF 侧布局模型 + TableFormer 质量在开源里第一梯队 |

收益与 03 篇直接相关: **父块边界依赖标题层级, chunk 元信息里的 `page_no` / `heading_path` / `chunk_type` 全部来自这里的解析结果**。代价(torch 级重依赖、首次下载模型、解析慢)在 [./01-环境与依赖.md](./01-环境与依赖.md) 已有预期管理, 接受。

### 2.2 保留结构树, 不"打平 Markdown 再正则切"

`doc.export_to_markdown()` 看着省事, 但打平后 label / level / prov 全丢, `heading_path` 与 `page_no` 只能猜。主路径是遍历结构树的 item 产出自有结构; Markdown 只用于**表格序列化**与调试导出(`doc.save_as_markdown()`), 不进主链路。

### 2.3 表格: 序列化为 Markdown + 整表原子

| 备选 | 弃选理由 |
|---|---|
| CSV | 表头与合并语义丢失, 逗号/换行转义脆 |
| HTML | 标签占字符, embedding 与 BM25 都在吃噪声 token |
| JSON / `export_to_dict()` | 保真最好, 但不可读、进不了 prompt, 行列与表头在检索时容易分家 |
| **Markdown(选定)** | 表头随身、LLM 读表最顺; 竖线行列文本经 jieba 分词后能被 BM25 以表头词精确命中 |

**整表一个 item、后续不切**(03 篇: 表格整块不切, 宁可超长): 表格从中间切开会毁掉行列结构, 每片都失去表头, 检索与生成双输。代价见 4.4。

### 2.4 图片: 落盘 + 占位文本, 描述生成默认关

图片块**不再只靠占位文本**参与检索: 图片落盘后其**文件路径会被 04 篇直接嵌入成真向量**(多模态 embedding `qwen3-vl-embedding`, 文本与图片映射同一向量空间), 图片块因此进 dense 路, 文本 query 可跨模态命中。占位文本仍写入 `text`(保证块非空, 稀疏路与文本展示不至于是无意义记录); `image_path` 进元信息, 随时可回溯原图。
`RAG2_IMAGE_DESC` 因此**降为可选增强**, 作用有二: 让图片块能被 BM25/关键词命中(占位文本只有路径与图注, 关键词面很窄), 让 06 篇评估的文本上下文可读。
代价(**开启前想清楚**): 每图一次 VLM/OCR 调用, 费用与 ingest 时长随图片数线性上涨; 单机本地系统也不该默认引入外部模型依赖(与本模块"不主动发起外部模型调用"的边界一致); 开关开启后重跑 ingest 就能补描述。

备选(不选): docling 自带 `do_picture_description` + `picture_description_options`(可挂 SmolVLM 之类的本地视觉模型, 官方示例存在)——无 API 成本, 但要多下一个视觉模型、Windows 上慢, 且把描述策略耦合进 converter 装配; 首版不做, 将来要加只是 4.1 里加三行。

### 2.5 噪声处理: parse 期白拿 furniture 判定, `clean.py` 用确定性规则兜底

docling 的 `DoclingDocument` 内建"正文 / 页眉页脚"区分——`body` 与 `furniture` 两棵根节点树(官方文档核实)。直接扔掉 furniture 下的 item 是零成本的; 但 docx/md 后端没有等价能力, 布局模型也会漏检, 所以 `clean.py` 自实现"跨页重复"兜底。分工: **parse 做白拿的、库版本相关的过滤; clean 做确定性、可单测、可解释的规则**——规则不随库版本漂移, 这也是 clean 能脱离 docling 单测的原因。

### 2.6 `doc_id` 内容寻址、`source` 相对路径(与 03/04 对齐)

- `doc_id = sha256(文件字节流).hexdigest()[:16]`, **解析阶段算好挂在 `ParsedDoc` 上**(03 篇 §2.4 定稿, 本篇透传): 同内容不同路径 → 同 `doc_id`, 重跑幂等; 内容变 → `doc_id` 变。
- 坑: 内容更新后旧 `doc_id` 的记录会残留 → 重灌时按 `source` 找出同源旧 `doc_id` 一并删除([./04-嵌入与Milvus索引.md](./04-嵌入与Milvus索引.md) 的 `delete_doc` 支持)。这是内容寻址换幂等的代价, 明确记录, 不隐藏。
- `source` = **相对语料根的 POSIX 风格路径**(`Path(...).as_posix()`), 单文件入库时退化为文件名; 语料根由 `ingest.py` 编排层确定, parse 只负责转换。

## 三、数据流与接口契约

```text
路径(str|Path)
  │ parse.py: 后缀白名单 → DocumentConverter.convert() → DoclingDocument
  ▼
DoclingDocument ──(遍历 items: 标题栈 / 表格转 MD / 图片落盘)──► ParsedDoc(原始)
  │ clean.py: 纯函数五条规则(不改顺序、不跨 item 移动内容)
  ▼
ParsedDoc(清洁) ──► 03 篇 chunk.py(父块聚合用标题边界, 子块用递归切分)
```

**`ParsedDoc`**(本篇产出, 字段语义如下; 形状以 [./07-接口设计与移植方案.md](./07-接口设计与移植方案.md) 为准):

| 字段 | 说明 |
|---|---|
| `doc_id` | 文件字节流 SHA-256 前 16 位 hex, parse 阶段计算(§2.6) |
| `source` | 相对语料根的 POSIX 路径, 与 chunk 元信息 `source` 同源 |
| `items` | `list[ParsedItem]`, 按文档阅读顺序排列 |
| `meta` | dict: 后端类型 / 页数 / 解析耗时 / warnings(字体映射失败等), 由 `ingest.py` 汇入 `IngestReport` |

**`ParsedItem`**(最小字段集):

| 字段 | 说明 |
|---|---|
| `type` | `text` \| `table` \| `image`, 直通 chunk 元信息的 `chunk_type` |
| `text` | 正文原文 / 表格 Markdown / 图片占位文本(非空) |
| `heading_path` | 标题面包屑, 各级以 `" > "` 连接(03 篇 §4.5 全模块约定); 无上级标题为 `""` |
| `page_no` | `int \| None`: pdf 取 `prov.page_no`; docx/md 无页码概念记 `None`(落库时由 04 篇写成 `-1` 哨兵, 见 04 篇坑位 7) |
| `level` | `int \| None`: **仅标题条目有值**(见下方对齐约定 1), 其它为 `None` |
| `image_path` | 仅 `type=image` 有值(相对 `RAG2_IMAGE_DIR` 的路径; 04 篇据此取图做多模态嵌入), 其余为 `None` |

**两条接缝约定(写代码前先记住)**:

1. **标题自身也产出条目**: 标题文本是检索关键词的载体, 同时是 03 篇父块的边界信号。约定为 `type="text"` 且 `level=<层级>` 有值, 其 `heading_path` **只含上级路径(不含自身)**——这样"标题不参与超短行合并、不被并进正文"是自然结果, 03 篇的标题栈也能直接 push。
   *命名对齐*: 03 篇骨架里的 `doc.units` 即本表的 `items`、`unit.kind == "heading"` 与本篇 `type == "text" and level is not None` 是同一信息的两种写法, `unit.char_len` 即 `len(item.text)`; 落地时以 `contracts.py` 定稿的字段名为准, 本表为准绳。
2. **`image_path` / `level` 都不属于九个固定 chunk 元信息字段**(`chunk_id, parent_id, doc_id, source, page_no, heading_path, chunk_type(text|table|image), char_len, created_at`, 父块同携、`parent_id` 为空)。图片路径落库时随其余透传元信息进 04 篇的 `metadata(JSON)`(并作为 04 篇读取图片本体做多模态嵌入的入口), 九字段命名不增不改。

**清洗统计**不新增契约类型: `clean.py` 返回 `(ParsedDoc, dict)`, dict 固定五个键——`{"garbled": 清掉的乱码字符数, "dropped_hf": 跨页重复的页眉页脚条目数, "deduped": 相邻重复条目数, "merged_short": 被合并的超短行数, "dropped_pagenum": 删掉的纯数字残片数}`(第五个键是规则 (5) 的附带项, 落地时补入), 由 `ingest.py` 汇总进 `IngestReport`; 另把规则 (1) 的两类解码级告警写进 `ParsedDoc.meta["warnings"]`。

## 四、实现要点(API + 骨架 + 坑位)

### 4.1 converter 装配(`parse.py`)

```python
# parse.py 骨架(教学说明用, 非完整实现)
from docling.datamodel.base_models import InputFormat
from docling.datamodel.pipeline_options import PdfPipelineOptions, TableFormerMode
from docling.document_converter import DocumentConverter, PdfFormatOption

def build_converter(cfg) -> DocumentConverter:
    p = PdfPipelineOptions()
    p.do_ocr = cfg.do_ocr                          # RAG2_DO_OCR, 默认关(见 §一 边界)
    p.do_table_structure = True

    p.generate_picture_images = True               # 抽图片本体(与整页图是两回事)
    return DocumentConverter(
        format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=p)},
        # allowed_formats=[InputFormat.PDF, InputFormat.DOCX, InputFormat.MD],  # 参数是否存在【待验证】
    )

# 使用: result = converter.convert(path); doc = result.document
# result.status 非 SUCCESS/PARTIAL_SUCCESS 一律按失败处理(4.7 坑位 1)
```

已核实: `format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=...)}` 构造形式、`do_table_structure`、`table_structure_options.mode`(`TableFormerMode.ACCURATE` 即官方默认档)、`images_scale`、`generate_picture_images`(官方 `pictures_description` 示例即用法)。

### 4.2 三种格式的解析差异

| 维度 | PDF | DOCX | MD |
|---|---|---|---|
| 解析路径 | 布局模型逐页推理 + TableFormer + 可选 OCR | OOXML 结构直读(规则驱动, 无模型) | Markdown 后端解析(无模型) |
| 标题层级 | 布局模型预测, **可能不准/不分级**(见 4.3 待验证) | 来自 Heading 样式/大纲级别, 最干净 | `#` 数量, 近乎无损 |
| 表格 | TableFormer 识别网格(含合并单元格) | 原生表格结构(含合并单元格) | **仅简单表格**: 源码里单元格一律 `row_span=1 / col_span=1`, 首行作 `column_header` |
| 图片 | 页面对象抽取, 需开 4.1 开关 | 内嵌媒体抽取 | 引用型(路径/URL), 无图片本体, `image_path` 记原引用 |
| `page_no` | `prov.page_no` 可靠 | 无页码概念 → `None` | → `None` |
| 首次运行 | 需下载 layout / TableFormer 模型 | 无 | 无 |

**`.doc` 坑**: docling 支持面里没有 `.doc`(1997 二进制格式, 无后端)。`parse.py` 对 `.doc` 后缀直接抛中文异常: "请先另存为 .docx(`soffice --headless --convert-to docx foo.doc` 或 Word 手动另存)"。**不做自动转换**——引入外部进程依赖不值当; 后缀与内容不符(改名冒充)会在后端深处报长堆栈, 入口校验 `path.suffix.lower()` 后给人话提示。

### 4.3 结构树 → `ParsedDoc` 的遍历骨架

```python
from docling_core.types.doc import DocItemLabel, ContentLayer   # 枚举拼写【待验证】

def walk(doc, doc_id: str, source: str) -> ParsedDoc:
    items, headings = [], []          # headings: [(level, title)] 标题栈
    for item, _lvl in doc.iterate_items():
        if getattr(item, "content_layer", None) == ContentLayer.FURNITURE:
            continue                  # 第一道: docling 判定的页眉/页脚/脚注
        page = item.prov[0].page_no if getattr(item, "prov", None) else None
        hp = " > ".join(t for _, t in headings)          # 非标题条目用它
        if item.label in (DocItemLabel.SECTION_HEADER, DocItemLabel.TITLE):
            lv = getattr(getattr(item, "heading", None), "level", 1)
            while headings and headings[-1][0] >= lv:
                headings.pop()                            # 回退到父级
            hp = " > ".join(t for _, t in headings)       # 弹栈后重算: 标题只含祖先, 别复用上面的 hp
            headings.append((lv, item.text))
            items.append(item_of("text", item.text, hp, page, level=lv))   # 标题自身成条目
        elif item.label == DocItemLabel.TABLE:
            items.append(item_of("table", item.export_to_markdown(doc), hp, page))
        elif item.label == DocItemLabel.PICTURE:
            items.append(item_of("image", "", hp, page, image_path=save(item, doc_id, page)))
        elif getattr(item, "text", None):
            items.append(item_of("text", item.text, hp, page))
    return ParsedDoc(doc_id=doc_id, source=source, items=items, meta={})
```

要点与坑:

- `iterate_items()` 按阅读顺序吐 `(item, level)`; **这里的 `level` 是结构树深度, 不是标题层级**, 别混用——标题层级是 `SectionHeaderItem.level` **直接字段**(2026-09-20 实测 docling 2.128.0: md `### ` → level=2, 即"# 数 − 1"); `TitleItem` 无 level(约定记 **0**)。
- **标题条目的 `heading_path` 必须在弹栈之后算**(先弹同级/更深的旧标题, 再拼面包屑): 复用弹栈前的值会把新章节挂到上一节下面——实测样例里"三、收尾"曾带上"二、图片", 而 03 篇的父块边界完全依赖这个值。
- **待验证**: PDF 的 `SECTION_HEADER` 是否携带可靠层级(布局模型可能全判 1), 以及空标题/过短标题的误判率。验证办法: 拿一份多级标题 PDF, 打印每个标题 item 的 `label / level / text` 看分布; 若层级不可用, 降级为"标题只做关键词载体, `heading_path` 退化为单级"并在 03 篇父块策略里写明(误判严重时在 parse 层加"过短标题丢弃"规则, 不在 03 篇修)。
- **待验证**: `TableItem.export_to_markdown(doc)` 的确切签名与 `DocItemLabel` / `ContentLayer` 枚举拼写。验证: `uv run python -c "from docling_core.types.doc import TableItem, DocItemLabel, ContentLayer; print([m for m in dir(TableItem) if 'export' in m]); print([l.name for l in DocItemLabel]); print([c.name for c in ContentLayer])"`。
- 遍历范围: 默认遍历的根通常是 `doc.body`, `doc.furniture`(页眉页脚)一般不出现——**两条路径都要兜住**(furniture 不出来靠 `content_layer` 判, 出来靠 4.6 规则判), 具体行为【待验证】: 打印 `doc.furniture.children` 与遍历结果的差集核对一次。

### 4.4 表格: 整表 Markdown 与合并单元格的坑

- 序列化用 `export_to_markdown(doc)`(或先 `export_to_dataframe()` 再 `to_markdown()`, 多一层 pandas 依赖, 不必); 失败兜底按 `item.data.grid` / `table_cells` 手拼(内部模型 `TableData.grid` 保留全部 span 元数据)。
- **合并单元格坑(官方文档核实的确定行为)**: Markdown 没有 rowspan/colspan 语法, 序列化器**只在起点格写值, 其余被覆盖的格子输出空**——即"摊平"。双层表头、斜表头等复杂表会出现整排空表头甚至行列观感错位; 检索仍可用(表头词还在文本里), 但**展示层不要依赖列对齐**。要保真时官方出口是 `export_to_html()` / `export_to_dict()`, 或自定义 `BaseTableSerializer`——首版不用, 记在这里备用。
- **单元格内换行/竖线坑(已实测, 不需要兜底)**: docling 2.128.0 的序列化器自己处理了——单元格内 `\n` 转空格、裸 `|` 转 `&#124;`(实测输出形如 `| 单元格 第二行 | 含&#124;竖线 |`)。所以 `clean.py` **不做** `<br>` / `\|` 替换(全量转义会把列分隔符一起毁掉), 只保留"表格 item 空白规整不破坏行结构"这条底线(非 `|` 开头的行并回上一行)。
- **跨页断表**: 一张表跨两页时 TableFormer 可能给出两个 `TableItem`。首版**不做自动拼接**, 靠 03 篇父块聚合(相邻 + 同 `heading_path`)把两张表放进同一父块, 检索上下文仍完整。
- **超长表格**: 整表不切后 `char_len` 可能远超父块目标 1200~1800; dense 侧截断策略交给 [./04-嵌入与Milvus索引.md](./04-嵌入与Milvus索引.md)(多模态模型的文本上限 32,000 token, 截断仅作极端兜底, 具体以 04 篇为准; 04 篇对超大父块还有 VARCHAR 上限的前置检查), BM25 侧不受影响。
- 验收抽 3 张表核对行列数(§五); 调试期把 `doc.save_as_markdown()` 导出人读版对照, 是最省事的排查手段。

### 4.5 图片: 落盘 + 占位文本 + 开关

```text
RAG2_IMAGE_DIR(默认 data/rag2_images/)
└── <doc_id>/
    ├── p0001_i000.png     # 第 1 页第 1 张
    └── p0007_i000.png
```

- 按 `doc_id` 分目录: 重跑 ingest 直接整目录覆盖, 不残留旧图; 文件名零填充便于排序; `image_path` 记**相对 `RAG2_IMAGE_DIR`** 的路径(整目录搬迁不失效), 统一 PNG(`RAG2_IMAGE_FORMAT=png|jpg` 可切)。
- 占位文本模板: `[图片 <序号>: <image_path>; 图注: <caption 或 "无">]`——含路径与语义词, 保证 `text` 非空(稀疏路与评估文本上下文的最小可读信息), 图片块的语义主体则由 04 篇的多模态向量承担。caption 是独立条目, 与图片在阅读顺序里相邻(可能在前也可能在后), 取 ±1 条目窗口内同页的 caption。
- 取图 API: 官方示例用 `PictureItem.image`(PIL 图像, 依赖 `generate_picture_images=True`); 另存在 `get_image(doc)` 一类取图方法——**具体入口【待验证】**(用 4.3 的 `dir(TableItem)` 同款命令查 `PictureItem`)。
- 开关 `RAG2_IMAGE_DESC=off|vlm|ocr`, **默认 off**, 定位是**可选增强**(图片块已由 04 篇的多模态嵌入拿到真向量; 描述的作用是让图片可被 BM25/关键词命中、让评估文本上下文可读): `vlm` 走独立配置的 OpenAI 兼容端点(`RAG2_VLM_API_BASE/API_KEY/MODEL`, 与 judge 的 `RAG2_JUDGE_*` 分开; 01 篇变量表未收录, 开启时再补), `ocr` 只对图片区域跑本地 OCR。**代价**(开启前想清楚): 每图一次串行调用, 百图文档 ingest 时长 + 数分钟; VLM 描述进 `text` 后**解析结果不再确定**(同一文档两次 ingest 文本可能不同), 跑 [./06-ragas评估.md](./06-ragas评估.md) 基线与新旧对比时必须冻结 `RAG2_IMAGE_DESC` / `RAG2_DO_OCR` 并在报告里注明。
- md 的引用型图片不搬文件、不联网抓取, 保持离线确定性。**实测修正(docling 2.128.0)**: md 后端**既不保留引用也不给图片本体**——`PictureItem.image` 恒为 `None`, `fetch_images` / `enable_local_fetch` / `enable_remote_fetch` 三种开关组合都试过, 都取不到 uri 或 PIL 图。所以这类条目 `image_path=None`、占位文本写 `[图片 n: 无本地图; 图注: ...]`, 检索只能靠占位文本 + 图注(图注在 md 里会另成一个普通 text 条目, 可被 BM25 命中); 要恢复引用得自己正则扫 md 源文本, 属 02 篇范围外的可选增强。

### 4.6 `clean.py`: 五条规则(逐项判定)

执行顺序: (1) 乱码/字符规整 → (2) 空白规整 → (3) 页眉页脚剔除 → (4) 重复元素去重 → (5) 超短行合并。**为什么这个顺序**: 归一化必须先做(否则重复比对与短行判定都不准); 剔除必须先于合并(否则页眉会被并进正文; 若先合并, 页眉已与正文焊接, 再也删不干净)。每步只做一类事, 单测逐规则覆盖。

**(1) 乱码/不可见字符清理**: 删 C0/C1 控制符(保留 `\n` `\t`)、零宽字符(`U+200B`、`U+FEFF`)、软连字符 `U+00AD`、私有区 `U+E000~U+F8FF`(嵌入字体图标); 正则删 `(cid:\d+)` 残留(PDF 字体未嵌入的经典乱码)。`U+FFFD` 替换符占比 > 1% → 整条 item 记 warning **不静默**(解码级问题, 清洗救不了, 该文档该走 OCR); 私用区占比 > 10% → 判定"字体映射失败"写入 `ParsedDoc.meta` 的 warnings。不做全半角标点强制统一(保留原文, 交给检索侧分词)。

**(2) 空白规整**: `\r\n`/`\r` → `\n`; 全角空格 `U+3000` 与不换行空格 `U+00A0` → 半角空格; 连续 ≥ 2 空格 → 1 个; 连续 ≥ 3 个 `\n` → `\n\n`; 每条 text 首尾 strip; 表格 item 内的换行按 4.4 转 `<br>`。**为什么必须做**: PDF 抽取常见"逐字空格 + 逐行换行", 不规整会让 03 篇子块的递归分隔符(段落 → 换行 → 中文句号)判断失准。

**(3) 页眉页脚剔除**(不依赖 bbox, 保持三格式通用):

- 规则 A(结构, parse 期已做): `content_layer == FURNITURE` 或 label 为 `page_header` / `page_footer` / `footnote` 的条目在解析阶段就不进 items(4.3)。
- 规则 B(跨页重复, clean 兜底): 判据全满足才剔——`type=text`、`level is None`(标题豁免)、归一化后长度 ≤ 50 字符、**出现在 ≥ max(3, 60% 页) 个不同 `page_no` 上**, 且该归一化键的全部出现**整组**剔除(只删命中的几页会留下残句)。归一化 = 去首尾空白 + 全角转半角 + 数字串替 `#`(吃掉页码)。典型命中: 逐页重复的公司名/文档编号/页码行/水印短句。页码全为 `None` 的 docx/md 不满足"不同页", 天然跳过, 符合预期。
- 规则 C(几何, 默认关): 需要 `prov.bbox`, 仅 pdf 有, 且"某页正文顶部恰好是标题"会误杀; 不实现, 只留 `RAG2_HF_GEOMETRIC` 开关位。
- 误伤风险与自查: 正文短句极少逐页原样重复, 风险低; 剔除条数记进 stats, 验收时抽查一份真实 pdf 的剔除清单。

**(4) 重复元素去重**: 相邻 ≤ 2 个条目内, 归一化(去空白与标点)后完全相等, 或 `difflib.SequenceMatcher(None, a, b).ratio() >= 0.95` 且长度 ≥ 20 → 保留先出现者(PDF 渲染抖动/双栏重排造成的重复条目)。跨页水印块是 (3) 的推广, 由规则 B 兜住。**保守阈值**: 目录与正文的同名标题天然相似但不相邻, 不受影响; 宁可少删——残留重复对检索的伤害小于误删正文。

**(5) 超短行合并**: PDF 布局模型常把每个视觉行切成独立 text item, 不合并则 03 篇子块会在行边界乱切。判据全满足才并: 前后相邻两个条目同为 `type=text`、`level is None`、`heading_path` 完全相同、后一个长度 < 30 字符 → 并入前一个; 拼接规则: 前一条目末字符是 ASCII 字母/数字则补一个空格(英文断行), 否则直接拼接(中文断行无空格)。长度 ≤ 4 的纯数字行(PDF 页码残片)单独出现时直接删。阈值可配(`RAG2_SHORT_LINE_MAX`, 默认 30)。**标题天然豁免**: 标题条目的 `level` 有值且 `heading_path` 不含自身, 不满足判据——这是 §三接缝约定 1 的回报。

```python
# clean.py 骨架(纯函数: 不 IO、不改原地、不跨条目移动内容)
def clean_document(doc: ParsedDoc, cfg) -> tuple[ParsedDoc, dict]:
    items = [_strip_invalid_chars(it) for it in doc.items]     # (1)
    items = [_normalize_ws(it) for it in items]                # (2)
    items, s1 = _drop_header_footer(items, cfg)                # (3) 规则 B
    items, s2 = _dedup_adjacent(items, cfg)                    # (4)
    items, s3 = _merge_short_lines(items, cfg)                 # (5)
    stats = {"dropped_hf": s1, "deduped": s2, "merged_short": s3}
    return replace(doc, items=items), stats
```
