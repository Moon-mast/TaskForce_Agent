# 02-入库侧全链路

> 一句话: 一个文件的字节流要经过**解析 → 清洗 → 分块 → 嵌入 → 落库**五段才成为可检索的数据, 这一步的目标不是"存进去", 而是"存成检索时好用的形状"。
> 对应实现: `src/rag_v01/parsers/`、`clean.py`、`chunk/`、`embed.py`、`store.py`、`pipeline.py`
> 前置: [01-设计构思与关键选型](./01-设计构思与关键选型.md) | 下游: [03-检索侧全链路](./03-检索侧全链路.md)
> 证据: `src/rag_v01/tests/test_parse.py` / `test_clean.py` / `test_chunk.py`(21 项) / `test_pipeline.py`(13 项); 真 pdf 实测 15 页/156 条目见 [rag_0.1/TODO 里程碑记录](../../../new_module/rag_0.1/TODO.md)

## 一、全貌与每段的输入输出

```text
文件路径
  │  parsers/__init__.py:parse_document(path, cfg, *, source)
  ▼
ParsedDoc(doc_id, source, items[], meta)      ← 结构树: 标题/正文/表格/图片, 带页码与面包屑
  │  clean.py:clean_document(doc, cfg) -> (doc, stats)
  ▼
ParsedDoc(已清洗)  +  stats{garbled, dropped_hf, deduped, merged_short, dropped_pagenum}
  │  chunk/split(doc, cfg) -> (list[ParentChunk], list[ChildChunk])
  ▼
父块 1200~1800 字 / 子块 450 字(重叠 50)      ← 九字段 + 父子 id 关联
  │  embed.py:embed_chunks(rows, warnings=...) -> list[list[float]]
  ▼
与子块一一对应的向量(1024 维)                 ← 文本走文本路, 图片走图片路, 按原下标拼回
  │  store.py:purge_stale → upsert_parents → upsert_children
  ▼
Milvus: parents(父块全文) + children(向量 + 内置 BM25)
  │  pipeline.py 汇总
  ▼
IngestReport(ok_sources, failed, total_parents, total_children, warnings)
```

**为什么顺序是这个顺序**: 清洗必须在分块之前(否则页眉会被焊进父块正文, 再也删不掉); 分块必须在嵌入之前(嵌入是按最终文本算的); `purge_stale` 必须在写入之前(否则会把自己刚写的删掉, 见 §六)。

## 二、解析: 从字节流到结构树

### 2.1 入口与格式白名单

`parsers/__init__.py:21` 的 `_FORMATS` 是**显式白名单**(`.pdf` / `.docx` / `.md`), 不靠 docling 去嗅探格式 —— 用扩展名判断可以给出一句人话报错, 而不是底层库的堆栈。三条边界: `.doc`(旧格式)被显式拒绝并提示转换(`:42-46`); 未知后缀报错; 文件不存在报错。后缀统一转小写(`:40`)。

### 2.2 docling 的用法要点

三处容易踩的地方(详细实测见 [rag_0.1/02 篇](../../../new_module/rag_0.1/02-文档解析与噪声处理.md)):

1. **解析配置按格式分文件给**(`parsers/pdf.py:18-28`): pdf 要开 `do_table_structure=True` + `TableFormerMode.ACCURATE` + `images_scale=2.0` + `generate_picture_images=True`(抽图必需); docx 用 MsWord 后端, 无模型、无页码; md 三个 fetch 开关全关(`md.py:21-29`), 换来确定性, 代价是 md 的图片永远取不到本体。
2. **走 `iterate_items()` 拿阅读顺序**: 先物化成一个列表(`common.py:98`), 因为图注要按前后邻居找; 同时**不读已废弃的 `doc.furniture`**, 改用 `item.content_layer`(`common.py:96`)。
3. **两条噪声过滤在解析期就做**(`common.py:104-107`): `content_layer == FURNITURE` 的条目(页眉页脚)直接丢; 再加一层显式 label 黑名单(`HEADER` / `FOOTER` / `FOOTNOTE`)。

### 2.3 结构树遍历: 标题栈

`parsers/common.py:82-152` 的 `walk()` 用一个**标题栈**把线性条目流变成带层级的结构:

- 遇到标题 → 按 `level` 弹栈到同层或更浅, **然后再算 `heading_path`**(`:119-124`)。顺序颠倒会让标题条目自带上一个同级标题的面包屑, 进而把父块边界带错 —— 这条是最容易写错的一处, 单测里专门有一例。
- `heading_path` **只含上级、不含自身**; docling 2.128 的 `TitleItem` 没有 `level`, 约定记为 0(`_TITLE_LEVEL=0`)。
- 页码取第一条 `prov`(`page_no_of`, `:42-45`); docx/md 没有 `prov` → `None`。

### 2.4 表格与图片

- **表格整表转 Markdown**(`common.py:155-184`): docling 2.128 已自行转义单元格内的换行与竖线, 所以这里**不做二次转义**(多做一次会把 `\|` 变成 `\\|`)。合并单元格会被摊平 —— 只在起点格写值, 这是 docling 的行为, 不是 bug。
- **图片落盘**(`parsers/images.py:20-37`): 路径 `{doc_id}/p{page:04d}_i{seq:03d}.{ext}`, 按 doc_id 分目录所以重跑同名覆盖; jpg 先 `convert("RGB")` 再 quality=92。
- **图注按邻居取**(`images.py:55-70`): `PictureItem.captions` 字段存在但恒空, 实测要按阅读顺序前后 ±1 找 TEXT 邻居, 长度上限 60 字。
- **占位文本恒非空**(`images.py:73-78`): `[图片 N: ref或"无本地图"; 图注: caption或"无"]` —— 保证图片块也能进 BM25 索引。md 取不到引用时**返回 `None` 而不是编造 `inline-image`**(`:40-52` 的注释记了这次教训: 编造路径会让上层以为真有引用)。

### 2.5 数据契约

`contracts.py:19-49`。`ParsedItem`: `type`(text/table/image, 用常量 `TYPE_TEXT/TABLE/IMAGE` 而非裸串, 拼错不会报错只会走错分支) / `text` / `heading_path` / `page_no` / `level`(仅标题有值) / `image_path`。`ParsedDoc`: `doc_id`(内容寻址) / `source`(入库时的相对路径, 单文件入库时就是文件名) / `items` / `meta`。

## 三、清洗: 五条规则, 顺序不能换

`clean.py:6-9` 明确写了顺序理由: **归一化必须最先, 剔除必须先于合并**。如果先合并, 页眉会被焊进正文行, 之后就再也认不出它是页眉了。

| 顺序 | 规则 | 判据 | 统计键 |
|---|---|---|---|
| 1 | 乱码修复 | 控制符(保留 `\t\n`)、零宽/BOM/软连字符、`(cid:n)`、私用区 | `garbled` |
| 2 | 空白规整 | 表格走专用分支(只压行内空白、丢空行、非 `\|` 开头的杂散行并回上一行) | — |
| 3 | 页眉页脚剔除 | 非标题 + 归一化后 ≤50 字 + 命中 ≥ max(3, 60% 页码) 个**不同页码**, 三条全满足才剔 | `dropped_hf` |
| 4 | 相邻去重 | **±2 条内**, 归一化相等或 `SequenceMatcher.ratio() ≥ 0.95`, 且两条都 ≥20 字; 标题不参与 | `deduped` |
| 5 | 超短行合并 | 相邻两条同为正文、`heading_path` 相同、后一条短于 `short_line_max` | `merged_short` |
| — | 页码残片 | 纯数字行(`^\d{1,4}$`) | `dropped_pagenum` |

三个刻意的设计:

- **整组剔除**: 规则 3 命中就把这一组页眉行全删, 不是删几页留几页 —— 只删几页会留下残句。
- **阈值保守到"宁可漏删"**: 规则 4 只处理相邻窗口、要求 0.95 相似度、还要求两条都够长; 非相邻的重复内容**故意不动**(那些可能是真重复的正文)。
- **两类问题只告警不静默**(`:85-107`): U+FFFD 占比 >1% 提示该走 OCR; 私用区占比 >10% 提示字体映射失败。清洗不会"假装修好了" —— 这是入库报告里 `warnings` 的来源之一。

## 四、分块: 父块聚合 + 子块切分

### 4.1 父块: 沿标题层级聚合

`chunk/parents.py:19-28` 的尺寸口径: `parent_target_chars = 1500`, 达标区间是 `×0.8 ~ ×1.2` = **1200~1800 字**。注意**下限只用来统计达标率, 不作为切分约束**(节点短就该小, 硬凑会把两节混在一起)。三条聚合规则顺序不可换(`:31-80`):

| 规则 | 内容 | 关键点 |
|---|---|---|
| A | 遇到同级或更浅的标题 → 闭合当前父块 | `level is None` 那支管"标题之前"的导言, **遇任何标题都闭合** |
| B | 将超过上限时闭合 | 判据是"**将要超**"而非"已经超" —— 差一个字的区别决定块长分布 |
| C | 收尾残余自成一块 | 宁小勿丢 |

外加两条:

- **标题进正文**(`:59`): 父块文本以标题开头。因为 BM25 只索引 `text` 字段, 标题里的词是最强的检索信号, 不放进正文等于自断一路。
- **表格/图片是原子块**(`:63-67`): 先闭合当前块, 再让它独占一个父块, 且子块阶段也不切(整表一条子块)。

最后 `absorb_heading_only`(`:83-114`)消掉"只有标题"的空壳父块(实测会产生 6~8 字的块), 并进紧随其后的那一个; 但**如果后一块自己就以标题开头**则不并(并了会让新节顶着上一节的面包屑)。

### 4.2 子块: 库负责递归, 重叠自己写

`chunk/children.py` 的切分由 langchain 的 `RecursiveCharacterTextSplitter` 负责, 但参数是刻意选的(`:35-51`):

| 参数 | 值 | 为什么 |
|---|---|---|
| `separators` | `["\n\n","\n","。","！","？","；",""]` | **末尾空串不能省**, 否则无标点长串整段不切(实测曾超上限三倍); 英文句点故意不入集(会切坏 `3.14`、`e.g.`) |
| `chunk_overlap` | `0` | **重叠自己加**: 库的重叠按整片量化, 做不到 40~50 的目标区间 |
| `keep_separator` | `True` | 配合 `_SEP_CHARS` 把库贴在片头的分隔符**搬回前一片尾** |
| `add_start_index` | `True` | 回查页码要用起点偏移 |
| `chunk_size` | 目标字符数 | 库按此严格封顶(实测 450 → 最长 448) |

**自研重叠**(`add_overlap`, `:77-105`): 取上一块尾部 `overlap` 字符的窗口, 再**回退到句界**; 对齐后的长度必须 ≥ 窗口 − 10, 否则裸取整个窗口(宁可重叠多一点, 也不要在句子中间截断)。上一块本身就 ≤ 窗口时**不重叠** —— 整块复制是纯噪声。

**页码回查按"加重叠之前"的起点**(`:141-146`): 重叠文本属于上一块, 用加了重叠的起点会把页码标错。

### 4.3 标题前缀只贴第一条

父块与子块两处都有这条规则(`chunk/__init__.py:62-67`、`children.py:141-146`): 退化切分把一节拆成多条父块/子块时, 标题前缀**只贴给第一条**, 否则会重复 N 遍。子块侧还有个细节: 用 `not children` 判断"是不是第一条", **不能用 `enumerate` 下标** —— 空片会被 `continue` 跳过, 下标就失准了。

### 4.4 契约: 九字段 + 父子 id

`contracts.py:52-92` 的 `Chunk` 基类九字段: `chunk_id` / `parent_id` / `doc_id` / `source` / `page_no` / `heading_path` / `chunk_type` / `char_len` / `created_at`, 外加一个**透传字段** `image_path`(不算九字段, 04 篇把它收进 metadata)。`char_len` 由 `text` 派生, 在 `__post_init__` 里用 `object.__setattr__` 钉死 —— 这是 frozen 数据类的官方逃逸口, 只为派生量开这一处。

id 规则: 父块 `{doc_id}:p{NNN}`、子块 `{doc_id}:p{NNN}:c{NNN}`(`chunk/__init__.py:71`、`children.py:149`)。这个格式后来被适配层用来反推 `seq`(见 [03 篇](./03-检索侧全链路.md) §八)。

## 五、嵌入: 分组拼回是生命线

`embed.py` 的双后端设计在 [04 篇方案](../../../new_module/rag_0.1/04-嵌入与Milvus索引.md) 里有完整论证, 这里只讲入库视角必须知道的三件事:

1. **文本与图片分组后按原下标拼回**(`embed_chunks`, `:218-259`): 两组分别调 API, 再按下标放回原位置。顺序错了 Milvus 照收不报错, 检索从此静默变差, 所以还有一个独立的条数校验(`_place`, `:262-272`)—— `zip` 在长度不等时是短截长、不报错, 只会整体错位一格。
2. **维度三处校验**(`_check_dim`, `:62-74`): 拿到向量立刻验, 报错直接点名 `RAG2_EMBED_DIM` 与"改维度必须重建 collection"。这是防线之一, 另两处见 [07 篇](./07-技术细节与坑位手册.md) 第 3 组。
3. **图片缺失按降级处理**: 有 `image_path` 但盘上没文件 → 记进 `dropped` 并告警, 图片块退化成用占位文本算向量。**md 文档属于正常降级**(它本来就没有本地图), 不记警告。

百炼 API 的两个硬限制写在常量里: 单请求文本 ≤20 条 / 图片 ≤5 条(`config.py` 的 `embed_batch` / `embed_img_batch`), 单图 ≤10MB(`_MAX_IMAGE_BYTES`, 本地先拦)。响应里带 index 时**按 index 重排**(`:127-130`)—— 多批并发后服务端可能打乱顺序。

## 六、落库: 两个 collection, 一份内容寻址

### 6.1 表结构

| collection | 字段 | 索引 |
|---|---|---|
| `children` | `chunk_id`(PK) / `parent_id` / `doc_id` / `source` / `chunk_type` / `page_no` INT64 / `text` VARCHAR(8192) `enable_analyzer=True` / `dense` FLOAT_VECTOR / `sparse` SPARSE_FLOAT_VECTOR / `metadata` JSON | `dense`: HNSW, COSINE, `M=16, efConstruction=200`; `sparse`: SPARSE_INVERTED_INDEX, BM25 |
| `parents` | `parent_id`(PK) / `text` VARCHAR(65535) / `doc_id` / `metadata` / `dense` FLOAT_VECTOR(dim=2, 占位) | `dense`: FLAT, COSINE(从不检索); `doc_id`: INVERTED |

三条设计要点:

- **BM25 是 Function, 不是字段**: `_child_schema:125-132` 声明 `text_bm25`, 输入 `text` 输出 `sparse`。入库 payload **不写 `sparse`**, 由服务端生成; 检索时 query 原文直传, **不要自己分词**(两侧口径必须一致)。
- **`parents` 的占位向量是被逼出来的**: Milvus 要求 collection 必须有至少一个向量字段、且每个向量字段都必须有索引才能 load, 于是给父块表加了一个 dim=2 的零向量 + FLAT 索引 —— 每行多 8 字节, 换"父块表能存在"。
- **`text` 的超长处理是跳过不是截断**(`upsert_children:386`): 超过 8192 **字节**的子块直接跳过并告警 —— 注意是字节不是字符, 中文约 3 字节/字, 8192 字节 ≈ 2700 汉字。

### 6.2 幂等与三道自检

`ensure_collections()`(`:182-199`)是幂等的: 不存在就建, 已存在就自检, 最后统一 `load()`。自检三道(`_check_children:202-225`)都是**错了不会当场报错**的类型, 所以必须主动查: dense 维度是否与配置一致、BM25 Function 是否在位、analyzer 的停用词是否生效。第三道 `_check_analyzer`(`:228-257`)抽验哨兵 token(`" "` / `"\n"` / `"的"`), 读不出 analyzer 配置时一律当"没有停用词"处理 —— 宁可让人重建表, 也不要带着污染的索引跑。

### 6.3 同源旧版本清理: `purge_stale` 必须在 upsert 之前

`doc_id` 是**内容寻址**的(files 的 sha256 前 16 位), 所以文件改一个字就是一份新文档。`store.purge_stale(source, keep_doc_id)`(`:528-552`)按 `source` 找到旧 doc_id 并整删, 顺序在写入**之前**(`pipeline.py:94-98`)—— 顺序颠倒会把刚写的数据删掉。`parents` 表没有 `source` 列, 所以先在 `children` 按 source 查出旧 doc_id, 再两表各删一次。

### 6.4 收尾只 flush 一次

`flush()`(`:270-278`)会把内存里的 segment 封盘并触发索引构建, 代价不小。所以 `pipeline.run_ingest` 是**整批写完只调一次**(`:46`), 不是每个文件调一次。副作用: 入库过程中查不到刚写的数据, 这是刻意的取舍(单用户场景不需要边写边查)。

## 七、编排: 逐文件处理 + 失败隔离

`pipeline.py` 的三条纪律:

1. **逐文件处理是硬约束**(`:1-7`): `ParsedDoc` 不留磁盘痕迹, 峰值内存 = 最大单文件 + 它的向量。批量入库 500 篇也不会把 500 篇的解析结果堆在内存里。
2. **单文件失败不影响整批**(`:34-44`): 异常进 `failed[source]`, 继续下一篇, 最后一起汇报。
3. **`source` 口径统一**(`expand_paths:56-75`): 传目录时以该目录为根, 传单文件时以父目录为根 → **单文件入库的 `source` 就是文件名**。这条口径上游被 API 依赖(上传后按文件名找 doc_id), 见 [dev/front/docs/API-CONTRACT.md](../../../../dev/front/docs/API-CONTRACT.md) §2.3。

调用顺序(`_ingest_one:83-99`): `parse_document → clean_document → split → embed_chunks → store.purge_stale → upsert_parents → upsert_children`。解析与清洗的 warning 合并进 notes, 再交给 embed 继续追加, 最后一并进报告。

## 八、谁在调用它

| 入口 | 调用方式 | 说明 |
|---|---|---|
| CLI | `python -m rag_v01.cli ingest <路径...>` | 支持目录递归; `list` / `delete` 直调 `store`, `search` 走检索 |
| REPL | `/kb upload <文件>` / `list` / `delete <doc_id>` | `src/cli/commands/knowledge.py`, 与 agent 读同一份数据 |
| HTTP | `POST /knowledge/upload` | `src/api/routers/knowledge.py`: 落临时文件(保留原名) → `ingest` → 按文件名回查 doc_id |

**上传接口的两个契约差异**(换内核时定的, 已登记在 [ROADMAP §7](../../../dev/ROADMAP.md)): `doc_id` 变成 16 位内容寻址 hash(不再是 32 位 uuid); `created_at` 恒为 `null` —— 内容寻址的库里**没有"上传时间"这个概念**, 文档只是子块的聚合, 没有独立的文档表。
