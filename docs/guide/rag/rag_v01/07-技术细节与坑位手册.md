## 第 1 组: Milvus 建表与存储约束

这一组是"库的硬规则逼出来的设计"。四条约束在 `store.py:6-14` 的注释里有实测记录(服务端 2.6.0 / pymilvus 2.6.17):

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 1.1 | `schema does not contain vector field`(1100) | Milvus 要求 collection **至少含一个向量字段** | `parents` 表加一个 dim=2 的零向量 `dense` + FLAT 索引, 每行多 8 字节换"表能存在"(`store.py:66-67`) | 建 `parents` 表时直接报错 |
| 1.2 | `no vector index`(65535) | **每个**向量字段都**必须**有索引才能 load | 同上: 占位向量也配 FLAT 索引 | 建表后 load 失败 |
| 1.3 | 向量字段 `nullable` 不支持(1100) | 库限制 | 不声明 nullable; 缺失语义用哨兵值表达(见 1.4) | 建表报错 |
| 1.4 | 维度下限 2, dim=1 被拒 | 库限制 | 占位向量用 dim=2 而不是 1 | 建表报错 |
| 1.5 | 超长子块"凭空消失" | VARCHAR 上限按**字节**算: `text` 8192 字节 ≈ 2700 汉字(中文约 3 字节/字) | 入库前用 `encode("utf-8")` 比字节, 超限**跳过并告警**(不静默截断) | 边界用例 + 代码注释 |
| 1.6 | `page_no` 为 `None` 写不进 INT64 | Milvus 标量列不接受 null | 入库 `None → -1` 哨兵, 检索再 `-1 → None` 还原(`store.py:402` / `retrieve.py:174-181`), **只在这两处转换** | 写入时报类型错 |
| 1.7 | `list_docs` 慢 | Milvus 没有 `GROUP BY` / `DISTINCT` | 客户端全量拉 `doc_id/source` 后聚合(`store.py:502-526`); 定位为**运维动作**, 不是检索热点 | 实现时确认库能力 |
| 1.8 | filter 表达式注入 | `filter` 是字符串拼接 | `_quote`(`store.py:328-337`): 含引号/反斜杠/换行直接拒绝, 不做"尽力转义" | 代码评审 |
| 1.9 | BM25 索引的 metric 只能是 BM25、类型只能倒排 | 库约束 | `_child_index`: sparse 用 `SPARSE_INVERTED_INDEX` + `BM25` | 建索引报错 |

## 第 2 组: 分词与 analyzer 治理

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 2.1 | 带空格的 query 召回一批无关子块, 且分数接近 | jieba analyzer 把**空白/标点也切成 token**(实测样例 20 子块 2540 token 中空格 1109 = **44%**, 竖线 331, 换行 62); RRF 只吃名次 → 噪声票与真信号票**等值** | 给 analyzer 配 138 个停用词 + 建表自检拦旧表 | 模块 05 冒烟时抓到(见 [03 篇](./03-检索侧全链路.md) §4.2) |
| 2.2 | 想加"去标点"filter 却报 `unsupport filter type` | 该 tokenizer **只支持 `stop`**; `removepunct` / `length` / `alphanumonly` / `lowercase` 全不支持 | 标点治理也只能靠停用词表 | 试错实测 |
| 2.3 | 改了词表却不生效 | analyzer 是**建表时写进 schema** 的, 不能原地更新 | 必须 drop 后重建 collection 并重灌语料 —— 这是 [08 篇](./08-调参与容量手册.md) "必须重灌的三类改动"之一 | 自检 + 文档 |
| 2.4 | 旧表带着被污染的 analyzer 继续用 | 自检读不出 analyzer 配置时若"放过", 就会带着脏索引跑 | `_check_analyzer` 抽验哨兵 token(`" "` / `"\n"` / `"的"`), **读不出就当"没有停用词"**, 宁可让人重建 | 设计决策(宁可误报) |
| 2.5 | 入库与查询的分词口径不一致 | 客户端自己分词再传 query | 稀疏路把 **query 原文直传**, 服务端用 schema 里的 analyzer 分词 | 设计约束 + 验收口径 |
| 2.6 | 手写的停用词表少了一个字符 | 全角标点串里漏掉一个 `*` | 单测断言覆盖(测试抓到的) | 单测 |

## 第 3 组: 嵌入与向量正确性

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 3.1 | 维度配置 1024, 实际返回 2560 | DashScope 多模态 API 的 `dimension` **必须走顶层 kwarg**; 写进 `parameters={...}` 会被**静默忽略**并返回默认 2560 | 用顶层 `dimension=cfg.embed_dim`(`embed.py:117-120`) | 实测对比两种写法 |
| 3.2 | 所有图片块静默退化成文本向量 | `image_path` 是**相对 `RAG2_IMAGE_DIR`** 的路径, 直接 `is_file()` 一律判假 → 走文本路, 无任何报错 | 判存在前先拼根目录(`_image_file`, `embed.py:76-85`) | 代码注释显式记录这条坑 |
| 3.3 | 维度错了却跑完入库 | 只在建表时校验一次不够 | **三处校验**: 建表自检(`_check_children`)、嵌入输出自检(`_check_dim`)、检索期维度一致性; 报错点名 `RAG2_EMBED_DIM` 与"改维度必须重建 collection" | 设计(三处都可能漏) |
| 3.4 | 检索质量莫名变差, 数据看着都在 | 向量与文本**错位**(`zip` 短截长不报错, 整体错一格), Milvus 照收 | `_place` 独立的条数校验(`embed.py:262-272`) + `upsert_children` 的"行数 ≠ 向量数直接抛" | 设计(静默失败最贵) |
| 3.5 | 多批并发后向量对不上文本 | 服务端可能重排返回顺序 | 响应带 index 时**按 index 重排**(`embed.py:127-130`) | 实现时防御 |
| 3.6 | 分数尺度不一致 / 换 IP 度量排名就变 | 未归一化 | 输出做 L2 归一化(`embed.py:36-45`); 对 COSINE 排名本身无影响, 目的是两后端尺度一致、分数落 [-1,1] | 设计 |
| 3.7 | SDK 不抛异常, 上层崩在 `output=None` | DashScope SDK 把错误放在响应对象里 | 非 200 **自己查 `status_code` 并抛**(`embed.py:121-126`) | 实测 |
| 3.8 | 单图上传失败 | 百炼限制: 单图 ≤10MB | `_MAX_IMAGE_BYTES` 本地先拦(10MB) | 文档 + 常量 |
| 3.9 | "配置了图片向量, 但库里没有图片向量" | 图片文件盘上不存在 | `embed_chunks` 记 `dropped` 并告警; **md 文档属正常降级**, 不记警告 | 设计(区分真降级与配置错) |

## 第 4 组: 分块边界

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 4.1 | 父块/子块文本里标题重复 N 遍 | 退化切分把一节拆成多条时, 每条都贴了标题前缀 | **标题前缀只贴第一条**; 子块侧用 `not children` 判断而不是 `enumerate` 下标(空片被 `continue` 会让下标失准) | 单测抓到(装配 bug) |
| 4.2 | 出现 6~8 字的"只有标题"空壳父块 | 标题后紧跟原子块或超长正文, 标题自己成块 | `absorb_heading_only` 并进紧随其后的一块; 但**后一块自己以标题开头则不并** | 实测样例 + 单测 |
| 4.3 | 无标点的长串整段不切, 超上限三倍 | `separators` 末尾少了空串 | 分隔符列表末尾**必须有 `""`**(硬切兜底) | 实测 |
| 4.4 | 子块开头多出标点、闭引号被切开 | 库的 `keep_separator=True` 把分隔符贴到下一片开头 | `_SEP_CHARS` 把分隔符**搬回前一片尾**, 并把尾随闭引号/括号一起搬 | 实测 + 单测 |
| 4.5 | 重叠落在句子中间 | 库的重叠按整片量化, 做不到 40~50 的目标 | 重叠**自己写**: 取尾部窗口后**回退到句界**, 对齐长度须 ≥ 窗口 − 10, 否则裸取整窗 | 实测 |
| 4.6 | 子块页码标错(跨页父块) | 用加重叠之后的起点回查 | 页码按**加重叠之前**的起点回查(重叠文本属于上一块) | 单测 |
| 4.7 | 表格/图片块被切成几段 | 判据写成了"是 table/image" | `block_type` 判据是**两条合取**: 块里只有一条内容单元 **且** 它是 table/image | 单测 |
| 4.8 | 标题被切成几字符的碎块 | 标题参与了切分输入 | `join_units` 把标题单独摘出**不进切分输入**; 退化切分的尺寸要**扣掉标题前缀与连接符长度** | 实测(父块超上限 1817 > 1800) |
| 4.9 | 标题条目的面包屑带上了上一个同级标题 | **先算面包屑再弹栈** | 顺序必须是**先弹栈再算**(`common.py:119-124`) | 单测 |
| 4.10 | 表格 Markdown 出现 `\\|` 双重转义 | docling 已自行转义, 这里又转一次 | 不做二次转义 | 实测 |

## 第 5 组: 清洗顺序与"不静默"

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 5.1 | 页眉被焊进正文, 再也删不掉 | 先合并超短行, 后剔除页眉 | 五规则顺序固定: 归一化 → 空白规整 → 页眉剔除 → 相邻去重 → 超短行合并(`clean.py:6-9`) | 设计说明 + 单测(换顺序会红) |
| 5.2 | 只删了几页页眉, 留下残句 | 页眉是跨页重复的一组, 逐页删会留半截 | **整组剔除**: 命中就删一组 | 实测 |
| 5.3 | 正文里的真重复被误删 | 阈值太松 | 相邻 **±2 条内** + 相似度 ≥0.95 + 两条都 ≥20 字; **非相邻不动**、标题不参与 —— 宁可漏删不误删 | 设计取舍 |
| 5.4 | 乱码/字体映射失败被"假装修好" | 静默丢字符 | 两类问题**只告警不静默**: U+FFFD 占比 >1% 提示走 OCR; 私用区 >10% 提示字体映射失败(`clean.py:85-107`) | 设计 |
| 5.5 | 表格被空行切断 | 空白规整把表格当普通文本处理 | 表格走专用分支: 只压行内空白、丢空行、非 `\|` 开头的杂散行并回上一行 | 实测 |

## 第 6 组: 融合与排序的可复现性

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 6.1 | 同分数值时顺序随机 → 评估回归不可复现 | 排序键不唯一 | **同分按 `chunk_id` 兜底**(`retrieve.py:75`) | 设计 + 单测 |
| 6.2 | 名次被抹平 | 先 `round` 再排序 | **先排序后 round**(`:84`, 排序用未 round 的原值) | 设计 |
| 6.3 | 名次口径混乱 | 用 0 当"未命中"哨兵, 与第 1 名的计算混淆 | 名次**从 1 起**, 未命中用 `None`(`ChildHit` 契约明确) | 契约 + 单测 |
| 6.4 | 基础设施故障被当成"没有资料" | 把异常吞成 `[]` | `search()` 的 `[]` **只表示库里确实没有**; 故障一律上抛(`retrieve.py:105-107`) | 专门的回归用例 |
| 6.5 | top-5 里 4 条来自同一父块 | 同父去重做在截断之前 | 顺序必须是**先截断再同父合并**(`:123-141`); 命中明细追加进已有条目, 父块全文不重复拼接 | 设计 + 单测 |
| 6.6 | 非法 `top_k` 白花一次 embedding | 校验位置太靠后 | `top_k` 校验在**调用 embedding 之前**(`:110-112`) | 设计 |
| 6.7 | 两路分数不可比却想加权 | 余弦分与 BM25 分量纲不同 | 用**名次**做融合(RRF)绕开归一化; 这也是否决线性加权的核心理由 | 选型论证 |

## 第 7 组: 流水线与状态

| # | 现象 | 根因 | 对策 | 怎么被发现 |
|---|---|---|---|---|
| 7.1 | 刚灌完的文件立刻消失 | `purge_stale` 在 upsert **之后**跑, 把新数据当旧版本删了 | 顺序固定: `purge_stale` → `upsert_parents` → `upsert_children`(`pipeline.py:94-98`) | 设计(内容寻址的必然后果) |

## 通用教训(从这 40 多条里抽出来的三条)

1. **静默失败比报错贵得多**: 向量错位、图片退化成文本、analyzer 带着脏词表跑 —— 这三类都不会崩, 只会让效果慢慢变差, 而且**发现时已经过了一轮评估的钱**。所以对它们的防御全是"主动自检 + 立即报错", 而不是"出了问题再查"。
2. **顺序即语义**: 清洗五规则、父块聚合三规则、`purge_stale` 与 upsert、截断与同父合并、先弹栈再算面包屑 —— 这些地方"看起来都是对的", 但换顺序就错。文档里凡是顺序相关的都写明了理由。
3. **库的实现会泄漏到调用方**: `total_cost` 是方法不是属性、嵌入基类要求八个别名、`keep_separator` 把分隔符贴在下一片头、`zip` 短截长不报错 —— 只读文档不够, 都得实测一遍。
