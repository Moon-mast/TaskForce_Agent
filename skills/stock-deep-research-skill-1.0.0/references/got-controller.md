# GoT（Graph of Thoughts）图控制手册

整合原 `got-controller`。当研究主题复杂、高风险、多空观点冲突、或需要策略性平衡深度与广度时，在股票尽调或通用研究流程之上叠加本模块。

灵感来源：[SPCL, ETH Zürich](https://github.com/spcl/graph-of-thoughts)。

## 核心概念

- **节点** = 研究发现、洞察、结论
- **边** = 发现之间的依赖与关联
- **分数** = 每个节点的质量评分（0-10）
- **前沿** = 可继续探索的活跃节点集合
- **操作** = 变换图状态的转换

## 5 种核心操作

### 1. Generate(k) — 从父节点创建 k 条新研究路径
**时机**：初始探索、扩展高质量发现、同时探索多角度。
**实现**：单条消息并行启动 k 个研究 agent，每个探索一个独立侧面。

Agent 模板：
```
你正在探索 [主题] 的 [具体侧面]。起点上下文：
[父节点内容]

任务：研究该侧面并提供：
1. 该侧面的关键发现
2. 带引用的支持证据
3. 置信度（High/Medium/Low）
4. 值得继续探索的关联侧面

以结构化节点形式返回发现。
```

### 2. Aggregate(k) — 将 k 个节点合并为一个更强的综合
**时机**：多个 agent 研究了相关侧面、需要合并成整体、解决来源矛盾。
**实现**：合并发现、解决冲突、提取关键洞察；通常在 2-3 轮生成之后。

Agent 模板：
```
你正在综合多个研究来源的发现。

输入发现：
[节点1内容] [节点2内容] [节点3内容]

任务：
1. 识别共同主题与共识点
2. 标注矛盾并解释差异原因
3. 创建综合全面的合成
4. 为合成结果打分（0-10）

输出：统一发现 + 冲突解决说明 + 质量分。
```

### 3. Refine(1) — 不新增研究，改进现有发现
**时机**：内容好但组织混乱、澄清模糊发现、补全引用。**阈值：节点分 ≥ 6.0**（实践中优先精修 ≥ 7.0 的节点）。

### 4. Score — 评估发现质量（0-10）
| 分数 | 标准 |
|------|------|
| 9-10 优秀 | 多个 A-B 级高质量来源，无矛盾，覆盖全面，引用完美 |
| 7-8 良好 | 来源充足，轻微模糊，主要点覆盖好 |
| 5-6 可接受 | 来源质量混杂，存在矛盾，覆盖有缺口 |
| 3-4 差 | 来源少或质量低，显著矛盾，不完整 |
| 0-2 极差 | 无可验证来源，重大错误，严重不完整 |

评分全程用同一标准，附评分理由，精修/聚合后重新评分。

### 5. KeepBestN(n) — 剪枝，只留每层前 n 名
**时机**：图过于复杂、聚焦高质量路径、防止节点指数膨胀。**剪枝标准：分 < 6.0 或内容冗余。**

## 3 种执行模式

### 模式 1：均衡探索（最常用）
```
迭代1: Generate(4) from root → 评分 [7.2, 8.5, 6.8, 7.9]
迭代2: 按分定策略 → 高分(8.5): Generate(2)深挖；中分(7.2,7.9): 各Refine；低分(6.8): 丢弃
迭代3: Aggregate(3) 最优节点 → 1 个综合节点
迭代4: Refine(1) 综合 → 最终输出
```

### 模式 2：广度优先（宽泛主题初始研究）
```
迭代1: Generate(5) → 评分 → KeepBestN(3)
迭代2: 从 3 个最优节点各 Generate(2) → 6 节点评分 → KeepBestN(3)
迭代3: Aggregate(3) → 最终综合
```

### 模式 3：深度优先（深挖单一高价值侧面）
```
迭代1: Generate(3) → 选最优（如 8.5）
迭代2: 仅从最优节点 Generate(3) → KeepBestN(1)
迭代3: 从最优子节点 Generate(2) → KeepBestN(1)
迭代4: Refine(1) 最终深度发现
```

## 决策逻辑速查

| 操作 | 触发条件 | 阈值 |
|------|---------|------|
| Generate | 开新路径、多角度探索、深挖 | 节点分 ≥ 7.0 |
| Aggregate | 多个相关发现待合并、需解决矛盾 | 2-3 轮生成之后 |
| Refine | 好发现需打磨、引用需补全 | 节点分 ≥ 6.0（优先 ≥ 7.0） |
| 剪枝/KeepBestN | 节点过多、低质量路径 | 分 < 6.0 或冗余 |

## 图状态管理

```markdown
## GoT Graph State

### Nodes
| Node ID | Content Summary | Score | Parent | Status |
|---------|----------------|-------|--------|--------|
| root | 研究主题 | - | - | complete |
| 1 | 侧面A发现 | 7.2 | root | complete |
| 3 | 侧面C发现 | 6.8 | root | pruned |
| final | 综合结论 | 9.3 | [1,2,4] | complete |

### Operations Log
1. Generate(4) from root → [1,2,3,4]
2. Score all → [7.2, 8.5, 6.8, 7.9]
3. KeepBestN(3) → 保留 [1,2,4]，剪除 [3]
4. Aggregate(3) → final
```

**状态值**：pending / in_progress / complete / refined / pruned / aggregated。

**持久化**（支持中断恢复）：
- `research_notes/got_graph_state.md` — 当前图结构
- `research_notes/got_operations_log.md` — 操作历史
- `research_notes/got_nodes/[node_id].md` — 各节点内容

## 与研究流程的集成

| 研究流程阶段 | GoT 操作 |
|-------------|---------|
| 检索规划 | Generate(3-7) 拆分子主题，评分排优先级 |
| 迭代查询 | Generate + Score 部署与评估 |
| 来源三角验证 | Aggregate 合并、解矛盾 |
| 知识综合 | Aggregate + Refine |
| 质量保证 | Score + Refine（< 8.0 则精修） |
| 输出 | 图定稿，产出最终报告 |

## 最佳实践

1. **从简入手**：首轮 Generate(3-5)
2. **积极剪枝**：分 < 6.0 立即剪，每轮生成后 KeepBestN(3)
3. **择机聚合**：不早于 2 轮生成、不晚于图失控
4. **选择性精修**：只精修高分节点，一次通常足够
5. **TodoWrite 跟踪**：每次图操作记入待办清单

## 成功标准

- [ ] 初始生成覆盖多元侧面
- [ ] 低质量路径早剪枝
- [ ] 高质量路径深挖
- [ ] 最终综合合并最优洞察
- [ ] 最终分 ≥ 8.5/10
- [ ] 总操作数 ≤ 10（效率约束）

**核心哲学**：宁深挖 3 条路径，不浅尝 10 条。并行探索 + 策略剪枝 = 高于串行研究的质量。
